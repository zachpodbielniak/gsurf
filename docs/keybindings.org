#+TITLE: gsurf Keybindings
#+OPTIONS: toc:2 num:nil

* Syntax

Bind keys under =keybinds:= in the config. A key string is an optional set of
modifier prefixes plus a [[https://gitlab.gnome.org/GNOME/gtk/-/blob/main/gdk/gdkkeysyms.h][GDK keyval name]]:

#+begin_example
"Ctrl+r"        "Alt+Left"      "Ctrl+Shift+g"      "slash"      "j"
#+end_example

Modifiers: =Ctrl= (=Control=), =Alt= (=Mod1=), =Shift=, =Super= (=Logo=/=Mod4=).
Order and case are normalized, so =ctrl+shift+g= and =Shift+Ctrl+g= match.

A single letter's case means Shift: =N=, =Shift+n= and =Shift+N= are all the same key (GDK reports Shift+n as the keyval =N= with the Shift modifier, and both spellings meet it). So =Ctrl+Shift+s= matches Ctrl+Shift+s as typed, and a lowercase =o= never fires for Shift+o. Caps Lock produces the uppercase keyval, so with Caps Lock on, =h= arrives as =H=, as in vim. Shift+Tab, which GDK names =ISO_Left_Tab=, matches =Shift+Tab=.

Punctuation follows the same idea. GDK reports a shifted punctuation key as its shifted keysym: Shift+period arrives as =greater=, Shift+bracketleft as =braceleft=. So with =Shift= in the binding, the unshifted name or its literal character is rewritten to that keysym, and =Ctrl+Shift+period=, =Ctrl+Shift+.= and =Ctrl+Shift+greater= are all the same binding (the tree sidebar's default toggle). Without =Shift= the name is kept, so =Ctrl+.= only fires for an unshifted period. The literal characters understood are =. , / ; ' [ ] - = ` \=, mapped on a US layout:

| Unshifted (literal)  | With Shift   |
|----------------------+--------------|
| =period= (=.=)       | =greater=    |
| =comma= (=,=)        | =less=       |
| =slash= (=/=)        | =question=   |
| =semicolon= (=;=)    | =colon=      |
| =apostrophe= (='=)   | =quotedbl=   |
| =bracketleft= (=[=)  | =braceleft=  |
| =bracketright= (=]=) | =braceright= |
| =minus= (=-=)        | =underscore= |
| =equal= (===)        | =plus=       |
| =grave= (=`=)        | =asciitilde= |
| =backslash= (=\=)    | =bar=        |

=+= separates modifiers, so a literal plus cannot be written; use =plus=.

Values are action nicks (see =gsurf --generate-yaml-config=). Both =-= and =_=
separators are accepted (=reload-nocache= or =reload_nocache=).

* Default bindings (core table)

| Key            | Action            |
|----------------+-------------------|
| =Ctrl+r=       | reload            |
| =Ctrl+Shift+r= | reload-nocache    |
| =Escape=       | stop              |
| =Alt+Left=     | back              |
| =Alt+Right=    | forward           |
| =Ctrl+plus/minus/0= | zoom in/out/reset |
| =Ctrl+f=       | find              |
| =Ctrl+g= / =Ctrl+Shift+g= | find next/prev |
| =F11=          | toggle-fullscreen |
| =Ctrl+q=       | quit              |
| =?=            | show-keybinds     |
| =o= / =Ctrl+l= | open-prompt       |
| =Ctrl+e= / =Ctrl+y= | scroll down/up |

Module default keys outside the core table include =Ctrl+Alt+f= (=form_autofill=, off by default): fill the focused form from the one autofill profile, or open the profile picker when there are several. It must carry =Ctrl=, =Alt= or =Super= because bare keys reach the page while a field is focused; see [[file:form-autofill.org][form-autofill.org]].

Some actions are performed by the module that owns their UI, through =GsurfActionHandler=: =open-prompt= by =chromebar= (the =--lrg= window draws its own address bar), =find= by =find_bar=, =tab-*= by =tabs=, and =follow-hints= / =enter-*-mode= by =modal=. With that module disabled the key does nothing and goes to the page.

Bare-letter vim navigation (=hjkl=, =gg=, =G=, =H=/=L=, =r=, =d=/=u=) is
provided by the =modal= module (enabled by default), not the core table, so it
is mode-aware and won't interfere with typing.

*Link hinting (vimium-style).* In normal mode, =f= overlays a short chord label
on every clickable element (links, buttons, inputs, ...). Labels are drawn from
=modules.modal.hint_chars= (default =asdfghjkl=) and grow from 1 to 2/3/4
characters as the number of targets increases. Type the chord to narrow the
set; as soon as one target remains it is clicked. =F= opens the chosen link in a
new view, and =Escape= cancels. Configure the keys/colors under
=modules.modal= (=hint_key=, =hint_key_newview=, =hint_chars=, =hint_bg=,
=hint_fg=, =hint_font_size=). Font size is a positive integer in CSS pixels, defaulting to =11=; invalid values retain the previous size and log a warning. Set =hint_font_size: 15= for larger labels in both =f= and =F= sessions.

In a C config, set =hint_font_size= in the embedded module YAML passed to =gsurf_config_load_from_data()=, as demonstrated by =data/sensible-config.c=. Supply the complete modules block: this loader replaces the retained modules mapping rather than merging individual options. Restart the browser with the rebuilt modal module to apply the change.

The =tabs= module adds =Ctrl+t= / =Ctrl+w= / =Ctrl+Tab= / =Ctrl+Shift+Tab=
(new/close/next/prev) and =Ctrl+Shift+t= (reopen), plus the tree sidebar keys: =Ctrl+Shift+.= (=tab-sidebar-toggle=), =Ctrl+Shift+[= (=tab-tree-collapse=) and =Ctrl+Shift+Page_Up= / =Ctrl+Shift+Page_Down= (=tab-move-up= / =tab-move-down=, moving the tab with its subtree). None of the tree keys overlaps a default binding; see [[file:tabs.org][tabs.org]]. =toggles= adds the =Ctrl+Shift+...= setting toggles.

The =wmux= module (off by default; [[file:wmux.org][wmux.org]]) adds tmux's keys. It runs before =modal= (priority -10), so its keys win. The prefix (=C-b=) sets the window's key grab, so the key after it reaches wmux even while you type in a page or the address bar.

Root table (no prefix; these replace the core =Ctrl+h/j/k/l= meanings while wmux is enabled, so =Ctrl+l= no longer opens the address bar: use =o= or rebind):

| Key   | Command          |
|-------+------------------|
| =C-h= | =select-pane -L= |
| =C-j= | =select-pane -D= |
| =C-k= | =select-pane -U= |
| =C-l= | =select-pane -R= |

Prefix table (=C-b= then the key; =r= marks a repeatable key, which works again without the prefix for =repeat_time= ms):

| Key                            | Command                                   |
|--------------------------------+-------------------------------------------|
| =%= / ="=                      | =split-window -h= / =-v= (a new tab in a new pane) |
| =C-%= / =C-"=                  | the same with =-c=: duplicate the page     |
| =o= / =;=                      | next pane / last pane                     |
| =Up= =Down= =Left= =Right= (r) | =select-pane= in that direction           |
| =C-arrows= (r) / =M-arrows= (r) | =resize-pane= by 1% / 5%                 |
| =x= / =z= / =q=                | kill pane (asks) / zoom / pane numbers    |
| ={= / =}=                      | swap with the previous / next pane        |
| =C-o= / =M-o=                  | rotate the panes up / down                |
| =Space= / =M-1= ... =M-5= / =E= | next preset / a preset / spread evenly   |
| =!=                            | break the pane into its own window        |
| =c= =n= =p= =l=                | new / next / previous / last window       |

The full table with every command is in [[file:wmux.org][wmux.org]]; both tables are configurable (=bindings:=, =root_bindings:=).

=dark_mode= binds =Ctrl+Alt+d= (=dark-mode-toggle=, everything on/off) and =Ctrl+Alt+Shift+d= (=dark-mode-toggle-site=, the current site, remembered across restarts); set =modules.dark_mode.key_toggle= / =key_toggle_site= to change or unbind them (see [[file:dark-mode.org][Dark mode]]). =Ctrl+Shift+d= belongs to the bookmarks module. The toggles module's legacy =keys.dark_mode= entry forwards to =dark-mode-toggle=.

The =containers= module (disabled by default) adds =Ctrl+Alt+t= (=container-new-temp=: a new tab in a temporary container) and =Ctrl+Alt+c= (=container-reopen-next=: reopen the tab in the next container), configurable as =key_new_temp= / =key_reopen_next=; see [[file:containers.org][containers.org]].

* Focus: the page and the address bar

The page has keyboard focus when the window opens and after every tab switch, so command keys work from the first keystroke.

- =o= (or =Ctrl+l=) focuses the address bar with its text selected: type to replace it.
- =Enter= loads the address and gives focus back to the page, so =j=/=k=/=f= work on what loads.
- =Escape= in the address bar abandons the edit: the bar shows the current URI again and the page takes focus.
- =Escape= in a page field (one you clicked, or one the page focused itself with =autofocus=) blurs the field, so the next key is a command again. This is core behaviour and works without the =modal= module.
- =Escape= anywhere else runs the =stop= binding.
- Shortcut chords that the address bar or find box doesn't use itself (=Ctrl+t=, =Ctrl+w=, =Ctrl+q=, =Ctrl+Tab=, =F11=, ...) still work while typing in them. Editing keys (=Ctrl+a=/=c=/=v=/=x=/=z=, arrows, Home/End) stay with the field.

The find bar (=/= or =Ctrl+f=) works the same way: =Enter= confirms the search and returns focus to the page, where =n= / =N= step through the matches. =n= / =N= are only taken while a search is up; =Escape= in the find box closes it and clears the highlight.

* Live help overlay (=?=)

Press =?= (the GDK keyval is =question=; =?= is accepted in C configs) to
open a popup listing every *currently active* binding:

- Core =keybinds:= table, with action descriptions.
- Each loaded, enabled module that implements =GsurfKeybindProvider=, using
  the keys it actually has after =configure()= (so a custom =key_new= or a
  disabled =tabs= module is reflected immediately).

GTK backends show a native dialog; other backends inject an in-page overlay.
While it is open:

- =j= / =k= move down / up through the list
- =h= / =l= scroll the panel left / right
- =q=, =?=, or =Escape= dismisses it

The list is rebuilt on every press — do not treat it as a static cheatsheet.

In a C config: =gsurf_config_set_keybind(config, "?", GSURF_ACTION_SHOW_KEYBINDS);=.

* Actions

Navigation: =back=, =forward=, =reload=, =reload-nocache=, =stop=, =home=,
=open-prompt=, =open-new-view=. Scroll: =scroll-{up,down,left,right,top,bottom}=,
=page-{up,down}=, =half-page-{up,down}=. Zoom: =zoom-{in,out,reset}=. Find:
=find=, =find-next=, =find-prev=. Tabs: =tab-{new,close,next,prev,reopen}=.
Modal: =enter-{normal,insert}-mode=, =follow-hints=. Misc:
=toggle-fullscreen=, =copy-url=, =paste-url=, =quit=, =show-keybinds=.

Handled by modules (the core table forwards them; each does nothing unless its module is enabled): tree sidebar (=tabs=, default keys =Ctrl+Shift+.=, =Ctrl+Shift+[=, =Ctrl+Shift+Page_Up= / =Page_Down=): =tab-sidebar-toggle=, =tab-tree-collapse=, =tab-move-{up,down}=. Containers (=containers=): =container-new-temp=, =container-reopen-next=. Dark mode (=dark_mode=): =dark-mode-toggle=, =dark-mode-toggle-site=. Autofill (=form_autofill=): =form-autofill=. Panes (=wmux=, or any module that installs a window layout and handles them): =pane-split-right=, =pane-split-down= — for the view they are dispatched with, split the pane showing it with a new tab when it is visible, otherwise split the active pane and show that view in the new pane (the =tabs= context menu dispatches them for a chosen tab); they have no default key. Kiosk mode refuses =container-new-temp=, =container-reopen-next= and the two pane splits like every action that opens a view.

* Modal / vim navigation

The =modal= module (enabled by default) provides vim-style navigation. It is
*focus-aware*, so it never blocks typing:

- When an editable element is focused — a page text field (=text=, =search=, =email=, =url=, =tel=, =password=, =number=, =date=, ... inputs), =textarea=, =select=, =contenteditable= or anything inside =role="textbox"= / =searchbox= / =combobox=, in the page itself, inside a shadow DOM component or inside an =iframe= — *or the address bar* — keystrokes go straight to it. You do *not* need to press =i= first, and no bare key (=o=, =a=, =i=, =f=, ...) is ever a command there. =Escape= blurs a page field, or leaves the address bar, and returns to command context.
- When nothing editable is focused (you're reading a page), bare letters are
  commands: =hjkl= scroll, =gg=/=G= top/bottom, =H=/=L= history, =r= reload,
  =d=/=u= half-page, =f= link hints (=F= follows in a new view).

There are two modes, as in vim:

| Mode   | Enter with                                                           | Keys                                                                 | Leave with                                                         |
|--------+----------------------------------------------------------------------+----------------------------------------------------------------------+--------------------------------------------------------------------|
| NORMAL | start (=start_mode: normal=), =Escape=                               | bare keys are commands; a focused field still gets its keys          | an insert key, =gi=                                                |
| INSERT | =i= or =a= (=modules.modal.insert_keys=), =gi=, =enter-insert-mode=  | every bare key goes to the page, field or not (web apps' own keys)   | =Escape= (also leaves the focused field) or =enter-normal-mode=   |

- =gi= (vimium) focuses the first visible text field of the page (shadow DOM included), puts the caret at its end and enters INSERT.
- =Escape= in INSERT returns to NORMAL *and* blurs the focused field, so the next key is a command, as in vim. In NORMAL it blurs a focused field, cancels a pending =g= chord, and otherwise reaches the core =Escape: stop= binding.
- =modules.modal.insert_keys= is a list of bare key names (default =[i, a]=; =[]= leaves only the =enter-insert-mode= action). The old =key_insert= / =key_normal= options never had an effect and are gone.

Focus is tracked by a small content script in every frame that reports DOM focus changes to the browser, so the right behavior happens automatically as you move between the page, form fields, and the address bar. It looks through open shadow roots (=document.activeElement= is only the shadow host there). Each frame reports on its own; a frame whose focus is in a child =iframe= stays silent, a "not editable" report from a subframe counts only if that frame holds the focused field, and a field reported by any frame wins, so an =iframe= loading late (a captcha, an ad) can no longer clear the state while you type in the page. Closed shadow roots are opaque to page scripts; a field inside one is not detected (use =i=/=a= there).

Even while a module holds the key grab (below) a bare key typed into a field is never a core command: if no module takes it, it goes to the page.

A module can take the next key away from a focused field with a *key grab* (=gsurf_window_set_key_grab()=): while it is set, every key goes to the keymap first, wherever focus is. =wmux= uses it for the key after its prefix (=C-b %= works while typing in a page field or the address bar); see "Window layouts (panes)" in =architecture.org=. =wmux= drops a pending prefix (and the =display-panes= numbers) when you click, when another view becomes active, or when the window loses focus, so the grab can never stay on and turn the next key typed into a field into a command.
