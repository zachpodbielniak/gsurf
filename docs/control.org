#+TITLE: gsurf Control Socket
#+OPTIONS: toc:2 num:nil

* Overview

Every gsurf (since 0.5) opens a /control socket/: newline-delimited JSON-RPC 2.0 over a Unix socket in the process's private runtime directory. =gsurfctl= ([[file:gsurfctl.org][gsurfctl.org]]) is its command-line client; scripts, editors and agents can speak the protocol directly. The socket is part of libgsurf, built into every gsurf, and on by default; it does not depend on =MCP=1= or the =mcp= module.

| Piece                    | Where                                    | Role                                                       |
|--------------------------+------------------------------------------+------------------------------------------------------------|
| =GsurfControlServer=     | =src/control/gsurf-control-server.{c,h}= | The listener, the JSON-RPC framing, the method registry, events |
| core methods             | =src/control/gsurf-control-methods.c=    | =instance.info=, =open=, =views.*=, =page.*=, =tree.*=, =layout.*=, ... |
| =GsurfControlProvider=   | =src/control/gsurf-control-provider.h=   | The module hook for extra methods                          |
| =GsurfControlClient=     | =src/control/gsurf-control-client.{c,h}= | Instance discovery and a client (sync, async, events)      |
| =gsurfctl=               | =tools/gsurfctl/gsurfctl.c=              | The thin command-line client                               |

The control headers are not part of =<gsurf.h>= (they use json-glib, which a crispy-compiled C config does not have); include =<gsurf/control/gsurf-control.h>=. =pkg-config gsurf= requires =json-glib-1.0=.

* Where the socket lives

- The socket is =$XDG_RUNTIME_DIR/gsurf/<pid>-XXXXXX/control.sock=, inside the directory =gsurf_runtime_dir_get()= creates (mode 0700, removed at exit together with everything in it). The socket itself is mode 0600.
- A connection whose peer runs as another user (=SO_PEERCRED= through =g_socket_get_credentials()=) is closed at once with a warning.
- An instance counts as running when its directory's =lock= file is held (the same non-blocking =flock()= probe the runtime-directory sweep uses, =gsurf_runtime_dir_is_live()=) and the directory has a =control.sock=. A live directory without one (an embedder that did not start a server, or =control.enabled: false=) is not an instance.
- With =control.name: NAME= the server keeps a symlink =$XDG_RUNTIME_DIR/gsurf/NAME.sock= to its socket, so =gsurfctl -i NAME= works. A stale link (its target's directory is dead) is replaced; a name a live instance holds is not taken (a warning says so). The link is removed when the server stops.

* Configuration

#+begin_src yaml
control:
  enabled: true      # default; false: no socket
  # name: work       # an instance name: letters, digits, '-', '_', '.'
#+end_src

In a C config: =config->control_enabled= and =config->control_name=. The section is read by the =gsurf= binary, which starts the server after the modules are activated (so their methods register) and stops it before the windows are torn down. =config.get= reports both keys.

* Wire format

One JSON value per line, in both directions (UTF-8, =\n=-terminated; lines up to 16 MiB). A request is a JSON-RPC 2.0 object; a batch is an array of them answered by one array.

#+begin_example
→ {"jsonrpc":"2.0","id":1,"method":"open","params":{"uri":"https://example.org","background":true}}
← {"jsonrpc":"2.0","id":1,"result":{"index":1,"id":4,"uri":"https://example.org/",...}}
→ {"jsonrpc":"2.0","id":2,"method":"no.such"}
← {"jsonrpc":"2.0","id":2,"error":{"code":-32601,"message":"unknown method 'no.such' (methods.list gives them)"}}
#+end_example

- =params= must be an object (named parameters) or absent; anything else is -32602.
- A request without =id= is a notification: it runs, and nothing is answered (not even an error).
- Answers may arrive out of order (=page.eval= waits for the page); match them by =id=.
- A batch answers with one array holding the answers of its calls (notifications left out); a batch of notifications answers nothing; an empty batch is -32600.

** Errors

| Code   | =GsurfControlError=                     | Meaning                                                         |
|--------+-----------------------------------------+-----------------------------------------------------------------|
| -32700 | =PARSE=                                 | The line is not JSON                                            |
| -32600 | =INVALID_REQUEST=                       | Not a request object (no string =method=), an empty batch       |
| -32601 | =METHOD_NOT_FOUND=                      | No such method                                                  |
| -32602 | =INVALID_PARAMS=                        | A parameter is missing or has the wrong type                    |
| -32000 | =FAILED=                                | The method failed (the message says why)                        |
| -32001 | =NOT_FOUND=                             | No such view, window, pane, container, module or key; no window |
| -32002 | =UNSUPPORTED=                           | Needs something not there: wmux, the tabs module, modal, a 3D window |
| -32003 | =PERMISSION_DENIED=                     | Refused by kiosk mode                                           |
| -32004 | =TIMEOUT= (client side)                 | No reply in time                                                |
| -32005 | =CLOSED= (client side)                  | The connection closed                                           |

A handler may also answer with a =G_IO_ERROR=: =NOT_FOUND=, =NOT_SUPPORTED=, =PERMISSION_DENIED= and =INVALID_ARGUMENT= map to -32001, -32002, -32003 and -32602 (=gsurf_control_error_to_code()=); the client maps codes back (=gsurf_control_error_from_code()=).

* Methods

Views are addressed by =view= (the stable id =gsurf_view_get_id()=, as =views.list= reports it) or, where noted, =index= (a position in the window); without either a method acts on the active view. The =lrg.*= methods (since 0.5.1) drive the =gsurf --lrg=3d= tab space of the active window; every one except =lrg.screenshot= answers with the =lrg.state= object after its change, and every change emits the matching =lrg.*= event. In any other window they fail with -32002 (=this window is not a 3D scene (start gsurf with --lrg=3d)=), and in a build without the scene with -32002 too (=this build has no 3D scene (build with LRG_BACKEND=1 LRG_3D=1)=). =config.get= also knows =lrg.arrangement=, =lrg.environment=, =lrg.background-fps=, =lrg.history-depth= and =lrg.reading-single-tab= (the configured values). See [[file:lrg-3d.org][lrg-3d.org]].

The =layout.*= methods go through the =GsurfWindowLayout= vfuncs (=describe=, =list_groups=, =list_panes=, =run_command=, =select_group=, =rename_group=, =show_view_at=), so wmux needed no new code and another layout implementing them is driven the same way. Without a layout they fail with -32002; in kiosk mode (which keeps wmux inactive) with -32003.

* Events

=events.subscribe= turns on the event stream for that connection; the connection can still call methods. Each event is a notification line:

#+begin_example
{"jsonrpc":"2.0","method":"event","params":{"topic":"view","event":"view.added","time":123456789,"data":{"view":4,"uri":"","title":""}}}
#+end_example

=time= is =g_get_monotonic_time()=. Core topics and events:

| Topic      | Events                                                          | =data=                                       |
|------------+-----------------------------------------------------------------+----------------------------------------------|
| =view=     | =view.added=, =view.removed=, =view.active=, =view.moved=       | =view, uri, title= (+ =from, to= for moves)   |
| =uri=      | =uri=                                                           | =view, uri, title=                           |
| =title=    | =title=                                                         | =view, uri, title=                           |
| =load=     | =load=                                                          | =view, uri, title, state= (started, redirected, committed, finished) |
| =mode=     | =mode=                                                          | =mode, label, passthrough, typing=           |
| =layout=   | =layout.groups=, =layout.visible=                               | =what=                                       |
| =download= | =download.started=                                              | =uri, suggested, destination= (null when the engine picks it) |
| =lrg=      | =lrg.arrangement=, =lrg.environment=, =lrg.reading=, =lrg.history=, =lrg.focus=, =lrg.pin=, =lrg.camera= | =what, arrangement, environment, reading, history= |

For one change the events come in the order the core emits its signals: a new foreground tab gives =view.added=, =view.active=, then =uri=, =load= and =title= as it loads. The download event comes from =GsurfModuleManager::download-started= (since 0.5), emitted once per download when its destination is decided; progress and completion are not reported. The =lrg= events (since 0.5.1) come from =GsurfLrgWindow::scene-changed= in a =--lrg=3d= window, whatever caused the change (a key, a pointer gesture, an =lrg.*= method, the end of the lone-tab reading mode when a second tab opens); =lrg.state= itself emits nothing. Modules may emit their own topics with =gsurf_control_server_emit_event()=.

* Providers: methods from modules

A module adds methods by implementing =GsurfControlProvider=:

#+begin_src c
static void
my_register(GsurfControlProvider *provider, GsurfControlServer *server)
{
	gsurf_control_server_add_method(server, "mymod.status", "My module's state", "{}",
		my_status, provider, NULL);
}

static void
my_iface_init(GsurfControlProviderInterface *iface)
{
	iface->register_methods = my_register;
}

G_DEFINE_FINAL_TYPE_WITH_CODE(MyModule, my_module, GSURF_TYPE_MODULE,
	G_IMPLEMENT_INTERFACE(GSURF_TYPE_CONTROL_PROVIDER, my_iface_init))
#+end_src

The server asks every active provider at start, after =modules.toggle=, and on =gsurf_control_server_refresh_providers()=; each refresh first removes every provider's methods, so a deactivated module's methods disappear. =methods.list= names the providing module. Name methods =<module>.<verb>=. A handler answers through its =GsurfControlInvocation= exactly once — =gsurf_control_invocation_return_value()= or =..._return_error()= — now or later (the server keeps the invocation alive until then; a second answer is refused with a critical).

* Client API

#+begin_src c
g_autoptr(GPtrArray) list = gsurf_control_list_instances(NULL);   /* GsurfControlInstance */
g_autoptr(GsurfControlClient) client = gsurf_control_client_new();
g_autoptr(JsonNode) tabs = NULL;

gsurf_control_client_connect(client,
	gsurf_control_instance_get_socket_path(g_ptr_array_index(list, 0)), &error);
tabs = gsurf_control_client_call(client, "views.list", NULL, &error);
#+end_src

- =gsurf_control_client_call()= blocks up to the timeout (=gsurf_control_client_set_timeout()=, 30 s default, 0 forever); =gsurf_control_client_call_async()= runs it in a worker thread for hosts that must not block their main loop.
- =gsurf_control_client_subscribe()= then =gsurf_control_client_read_event()= read the event stream; events that arrive during a call are queued, not lost.
- =gsurf_control_find_instance(NULL, "work")= resolves a pid, a name or a directory id.

* Embedding

The library never opens a socket by itself. An embedder that wants one creates =gsurf_control_server_new(app)= (or =NULL= to use the default module manager's application), optionally =gsurf_control_server_set_name()=, and =gsurf_control_server_start(server, NULL, &error)= after its modules are active; =gsurf_control_server_stop()= (or the last unref) removes the socket. =open= builds views the way the gsurf binary's tab paths do (=gsurf_view_new_full()=, settings applied, =gsurf_window_add_view()=), so the host's =view-added= wiring applies; =action.run= needs the host's action executor for the core actions (=gsurf_module_manager_set_action_executor()=). =gsurf_control_server_dispatch()= runs a request line in-process, without a socket.

* Security

- Same-user only: 0700 directory, 0600 socket, peer-credential check.
- Anything that can connect can run JavaScript in your pages (=page.eval=), read them and open URLs. That is the same trust as the user's own shell; do not expose the socket (no forwarding over SSH without thought).
- Kiosk mode refuses opening, reopening and navigating views, =page.eval=, module toggles, and the actions kiosk forbids on the keyboard. =config.enabled: false= removes the socket entirely.

* Relation to MCP

The =mcp= module ([[file:mcp.org][mcp.org]]) is an MCP server for AI clients, opt-in per tool and only in =MCP=1= builds. The control socket is the always-available scripting interface with the same reach (both use the same core seams); an agent with a shell can use =gsurfctl= without MCP.
