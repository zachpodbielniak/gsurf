#+TITLE: gsurf Modules
#+OPTIONS: toc:2 num:nil

Modules are loadable =.so= extensions — gsurf's equivalent of surf patches. Each
is enabled under the =modules:= section of the config. See [[file:module-system.org][module-system.org]] to
write one. =gsurf --list-modules= prints the registry in alphabetical order.

Status: *implemented* modules ship and are tested; *planned* modules are designed
(registry entry + config schema present) and follow the established pattern.

* Per-module documentation

Detailed docs live under =docs/modules/<name>.org= as each module lands. The
=search_engines= and =mcp= modules are the reference implementations.

* Search routing

The =search_engines= module trims surrounding ASCII whitespace before matching input. Prefixes remain case-sensitive literal strings: include a trailing space when a keyword should require a word boundary. If several prefixes match, the longest wins, so =g = can search the web while =g site = searches a particular site. Explicit prefixes take precedence over address detection. Queries are URI-escaped before replacing the first =%s= in the template; templates without =%s= append the escaped query.

Default search applies only when no prefix matches and normalization does not produce a URI. That covers explicit schemes (=mailto:=, =magnet:=, =javascript:=, =about:=, =gopher:=, =gemini:=, =view-source:=, and any other scheme, including uppercase spellings), bare dotted hosts, =localhost= addresses, and filesystem paths. Paths become =file://= URIs in =gsurf_view_normalize_uri()= before the view loads them; search routing only has to leave them alone. Passing a scheme through does not promise that the selected backend supports it. =localhost tutorial= and tab-separated phrases remain searches. An explicit engine prefix wins over a path, so =g /etc/hosts= is a search. Empty or whitespace-only input does not generate a search request.

Empty URL templates are ignored. Empty prefixes do not match every address; an engine with an empty or omitted prefix may still serve as the named default. Each configuration call replaces the module's previous routing state: removed engines, missing defaults and absent module sections cannot leave old search destinations active. Omitting =default_is_search= restores its default of =true=.

The =/gsurf/modules/search-routing= and =/gsurf/modules/search-reconfigure= regressions load the real module and exercise manager dispatch without a display or network connection.

* Reconfiguring settings modules

When a host calls =gsurf_module_configure()= again, a supplied =uri_params.rules= or =useragent.rules= sequence replaces that module's previous rules. An empty sequence (=rules: []=) removes all rules; omitting the sequence preserves it. New user-agent rules take effect immediately instead of being masked by earlier first-match rules.

A supplied =useragent.presets= mapping likewise replaces the previous mapping, including an empty =presets: {}=. Presets are resolved when rules are configured, so supply the rules again when changing their preset definitions. Unrecognized preset names remain literal user-agent strings. Options omitted from the update retain their previous values.

Module priorities are signed integers, ordered from lowest to highest when modules are added and when =gsurf_module_manager_activate_all()= runs. The full =gint= range is supported; changing priorities after activation requires another activation pass to reorder dispatch.

* History records and storage

History defaults to =$XDG_DATA_HOME/gsurf/history= (normally =~/.local/share/gsurf/history=). The shipped configurations leave =file= unset to honor that default; a custom =file= still supports =~/=. Reconfiguring =log_titles= without =file= preserves the selected destination. An explicitly empty =file: ""= disables writes. Storage is created only on the first eligible visit, with mode =0700= for new directories and =0600= for new files, subject to the process umask; existing permissions are preserved.

Each visit appends one line: URI, an optional tab and title, then a newline. ASCII control bytes in URIs are percent-encoded, while ASCII controls in titles become spaces. Existing percent escapes and UTF-8 text are preserved. This keeps page titles from injecting additional records or terminal control bytes. =about:= and =data:= visits are excluded regardless of scheme casing. Existing log contents are not rewritten or sanitized retroactively.

Directory creation, opening, writing and closing failures produce warnings containing the affected path and error. Later visits retry normally after a storage failure; failed records are not queued for replay. This remains an append-only text log, not a transactional database or a guarantee against disk loss. =tests/test-history.c= covers the real module with temporary XDG storage and a model-only view, without a display or network access.

* Hosts-file parsing and download destinations

The adblock module accepts bare domains and hosts-file lines with an IPv4 or IPv6 address followed by one or more hostname aliases. It ignores blank lines and comments, including trailing =#= comments. Hostnames are normalized to lowercase ASCII (including internationalized domain names), with a trailing DNS root dot removed. Blocked and whitelisted domains match whole labels and their subdomains; whitelist matches take precedence. Invalid non-host tokens are excluded from generated filter JSON.

The downloads module treats the suggested name as a filename: it strips directory components, substitutes =download= for empty names, dot components and roots, and resolves relative =dir:= settings against the process working directory. Directory creation failures are logged and leave destination handling to the engine. This is filename containment, not a guarantee against another local process replacing directory entries; existing WebKit overwrite behavior is unchanged.

* Chrome module lifetime

The =chromebar=, =find_bar=, =status_bar= and =tabs= modules build and behave the same on GTK3 and GTK4. They share the header-only, module-private =modules/include/gsurf-chrome-compat.h=, which maps each GTK call to the GTK3 API or to its non-deprecated GTK4 equivalent (for example =gtk_editable_get_text()= for entry text, since a GTK4 =GtkSearchEntry= is not a =GtkEntry=, and =gtk_widget_set_visible()= instead of show/hide).

On deactivation each module disconnects its window and view signals and its key handler, and detaches its widget from the window chrome: =gtk_widget_destroy()= on GTK3; on GTK4 =gtk_box_remove()= (or =gtk_widget_unparent()= for a non-box parent), and nothing when the host container is already gone. Reactivation creates one new widget. Disposal performs the same idempotent cleanup, including when an embedding host retains a window, view, or native widget after releasing its module manager. Modules retain their native widgets until cleanup (=find_bar= retains both its bar and its search entry, because GTK3 destroys a container's children with it; =tabs= retains its strip, its sidebar, the sidebar's list and every row) so destroying the host container first does not leave dangling widget pointers. =tabs= also releases everything when its window finalizes first (it holds a weak reference on it).

Key handling in the address bar and find bar runs before the entry's own: a =key-press-event= handler on GTK3, a =GtkEventControllerKey= in the capture phase on GTK4 (so it also precedes the entry's inner =GtkText=). Escape in the address bar restores the page URI and returns focus to the page; Enter loads the input. In the find bar, Enter confirms the search and returns focus to the page (where =n= / =N= step), Shift+Enter steps backwards without activating, and Escape clears the query and highlight and hides the bar. On GTK3 the hidden find bar sets no-show-all so the window's startup show-all does not reveal it; GTK4 has no show-all, so it is simply hidden.

Switching tabs refreshes the status bar from the new view's current load progress. Removing the last view clears both the address and status text.

The regression suite =tests/test-chrome-lifecycle.c= loads the real shared modules with model-only views and a GTK box standing in for the window chrome, without launching a web process or making network requests, on both backends. It covers tab state, deactivation (twice), reactivation, retained widgets, repeated disposal, the host container dying first, the address-bar and find-bar keys (delivered as =key-press-event= on GTK3 and through the module's named key controller on GTK4), the address bar's mode indicator (following =GsurfModuleManager::mode-changed=, =mode_hide_normal=, =mode_indicator: false=, a bad colour), primary row clicks acting on release, and the =tabs= strip and tree sidebar (see [[file:tabs.org][tabs.org]]; row clicks are delivered as =button-press-event= (=button-release-event= for the primary button) on GTK3 and through the row's named =GtkGestureClick= on GTK4). It needs a display and is skipped by =make test= unless =GSURF_TEST_GUI= is set; =make test-gui= runs it under Xvfb, or run =GSURF_TEST_GUI=1 ./build/release/test-chrome-lifecycle= with a display (it presents no window).
