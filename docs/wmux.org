#+TITLE: wmux: a tmux-style web multiplexer
#+OPTIONS: toc:2 num:nil

* Overview and mental model

wmux is tmux for the web, inside one gsurf window. It is a module (=modules/wmux/=, =wmux.so=), off by default.

| tmux                 | wmux |
|----------------------+------|
| session              | the browser window |
| window               | a *tmux window*: one arrangement of panes; a browser window has as many as you create (=C-b c=), one of them current |
| pane                 | a viewport showing one tab |
| a program in a pane  | the tab (a web view) the pane shows |

Every pane shows one tab of the browser window. The tabs that no pane shows are *background tabs*: they stay open, stay in the tab strip and the tree sidebar, and keep their pages; selecting one (a sidebar click, =Ctrl+Tab=, =gt=) shows it in the active pane, and the tab shown there before becomes a background tab. The tabs shown by the panes of another tmux window are background tabs of the screen too: selecting one switches to that tmux window. The *active pane* is the one with the keyboard focus; its tab is the window's active tab, so everything that acts on "the current tab" (the address bar, =o=, reload, find, hints, the core keybinds) acts on the active pane.

A three-pane tmux window next to the tab tree (=C-b %= on the first tab, then =C-b "= on the new one):

#+begin_src text
+------------+--------------------------+---------------------------+
| Tabs       | GitHub                   | docs                      |
|            |                          |                           |
| > GitHub   |                          |                           |
|   docs     |   pane 0                 |   pane 1  (active,        |
|   mail     |                          |            brighter,      |
|   news  .. |                          |            wider border)  |
|            |                          +---------------------------+
|            |                          | mail                      |
|            |                          |   pane 2                  |
|            |                          |                           |
+------------+--------------------------+---------------------------+
| [gsurf] 0:docs* 1:news-                                      2/3   |
+--------------------------------------------------------------------+
#+end_src

=GitHub=, =docs= and =mail= are shown in panes; =news= is a background tab (it is the only pane of tmux window 1). The status line lists the tmux windows (=*= the current one, =-= the last one) and, on the right, the active pane's number and the number of panes (and =Z= while zoomed).

The module is built from a toolkit-neutral core and a GTK front end. The core is four pure-GLib parts in =modules/wmux/=, compiled straight into their unit tests:

| File                                 | Role |
|--------------------------------------+------|
| =modules/wmux/gsurf-wmux-layout.c=   | The pane layout model (an n-ary split tree with integer weights), its operations, exact pixel geometry, the layout string, and the window-state string the session module stores. |
| =modules/wmux/gsurf-wmux-command.c=  | The command language: a tmux subset, tokenized, parsed and validated into a struct; one canonical printer. |
| =modules/wmux/gsurf-wmux-keys.c=     | Key notation: tmux and gsurf spellings and key events, all mapped to one canonical name. |
| =modules/wmux/gsurf-wmux-bindings.c= | Binding tables (key to command, repeatable flag), the default prefix and root tables, merging config overrides, validation. |

The front end:

| File                                    | Role |
|-----------------------------------------+------|
| =modules/wmux/gsurf-wmux-module.c=      | The module: configuration, keys (prefix, key grab, repeat, root table), the command interpreter, the =pane-split-*= actions, keybind help, activation. |
| =modules/wmux/gsurf-wmux-session.c=     | The tmux windows of the browser window and every operation on them; the =GsurfWindowLayout= implementation (the window hands views in and out, activates them, asks what is visible, saves and restores the arrangement). |
| =modules/wmux/gsurf-wmux-ui.c=          | The widgets: pane frames in the grid, the status line with its prompt, the chooser, the pane numbers; the stylesheet. GTK3 and GTK4 through =modules/include/gsurf-chrome-compat.h=. |
| =modules/wmux/gsurf-wmux-grid-gtk3.c=, =gsurf-wmux-grid-gtk4.c= | The pane grid, a custom container per toolkit (the module Makefile picks one by =GTK_BACKEND=): it places each pane frame at its rectangle from the model's geometry and turns drags on the gaps into border moves. |

wmux installs itself as the window's =GsurfWindowLayout= (see [[file:embedding.org][embedding.org]]): its root widget takes the place of the window's view stack, and the window hands it every view.

* Quick start

Enable it in =~/.config/gsurf/config.yaml=:

#+begin_src yaml
modules:
  wmux:
    enabled: true
#+end_src

The five keys to learn first:

| Keys          | Does |
|---------------+------|
| =C-b %=       | split: a new pane to the right, showing a new tab |
| =C-b "=       | split: a new pane below |
| =C-h/j/k/l=   | move to the pane left / below / above / right (no prefix) |
| =C-b x=, =y=  | close the pane (and its tab) |
| =C-b z=       | zoom the pane to the whole window, and back |

Then =C-b c= for a new tmux window, =C-b n= / =C-b p= to cycle them, =C-b w= to pick a window or pane from a list, =C-b q= to see pane numbers, =C-b ?= for every key.

What changes with wmux on:

- =C-h/j/k/l= always move between panes. =C-l= no longer opens the address bar: use =o= (modal) or rebind (see the cookbook).
- =o= (the open prompt) and the address bar load into the active pane.
- A click in a pane makes it the active pane.
- The sidebar and the strip still list every tab. Selecting a tab shown in a pane focuses that pane; selecting a background tab shows it in the active pane. Tabs shown in a pane are highlighted (=gsurf-tab-row-visible=), and the tab menu offers *Open in Split Right* and *Open in Split Below*.
- =Ctrl+t=, a link opened in a new tab and a popup open in the active pane (the tab there becomes a background tab). =C-b %= opens one in a new pane instead.

* How panes, tabs and windows behave

** Splitting

=split-window= splits the active pane (=split_ratio= percent for the new pane) and shows a *new tab* in the new pane, placed like =Ctrl+t= (the containers module's new-tab policy picks its container; it opens =browser.new_view_uri=). With Ctrl held (=C-b C-%=, =C-b C-"=, =split-window -c=) the new pane shows a *copy of the current page* in the same container, as a child of the current tab in the tree. A split that would make either pane smaller than =min_pane_pct= of the window is refused with a message in the status line. The new pane becomes active unless =-d= is given.

** Selecting a tab

When the window makes a tab active (the sidebar, =gt=, =Ctrl+Tab=, a new tab, a popup, a focused page):

- a pane of the current tmux window shows it: that pane becomes active;
- a pane of another tmux window shows it: wmux switches to that window and that pane;
- no pane shows it: the active pane shows it, and the tab shown there before becomes a background tab.

** Closing

- *kill-pane* (=C-b x=) closes the pane. With =on_pane_kill: close_tab= (the default) its tab closes too; with =keep_tab= the tab stays as a background tab. The only pane of a tmux window closes that window (as in tmux). The last pane of the last window is never removed: a new blank tab takes its place.
- *A tab shown in a pane closes* (=Ctrl+w=, the close button, a script): with =on_tab_close: close_pane= (the default) its pane closes; the last pane of the last window then shows the next background tab. With =keep_pane= the pane stays and shows the next background tab (or stays empty when there is none).
- *kill-window* (=C-b &=) closes the current tmux window and its panes (their tabs per =on_pane_kill=); the last window is replaced by a fresh one with a blank tab.
- *Reopening a tab in another container* (the tab menu, =C-Alt-c=, the containers module) replaces its view; the new view takes the old one's pane.

** Zoom, numbers, layouts

- =C-b z= zooms the active pane to the whole area; the status line shows =Z=. Selecting another pane, splitting, closing, swapping, rotating, resizing and changing the layout unzoom.
- =C-b q= shows each pane's number (its index in layout order: left to right, top to bottom) in large type for =display_panes_time= ms; pressing a digit meanwhile selects that pane, any other key hides the numbers.
- =C-b {= / =C-b }= swap the active pane with the previous / next one, =C-b C-o= / =C-b M-o= rotate all of them; the tabs move with the panes.
- =C-b Space= cycles the presets =even-horizontal=, =even-vertical=, =main-horizontal=, =main-vertical=, =tiled=; =C-b M-1= ... =M-5= pick one; =C-b E= spreads the active pane and its siblings evenly.
- =C-b= then an arrow with Ctrl (1%) or Alt (5%) resizes; with =mouse: true= a drag on the gap between two panes moves that border.

** The status line

The status line sits under the panes (=status_position: top= puts it above): =[gsurf]=, one entry per tmux window (=0:GitHub*=, =1:docs-=, =2:mail=), and the active pane's number and the pane count on the right (=2/3=, plus =Z= while zoomed). =*= marks the current window and =-= the last one. A window is named after the page title of its active pane (cut to =window_name_max= characters) until it is renamed (=C-b ,=, =rename-window=, =new-window -n=); renaming it to nothing goes back to automatic naming. Clicking an entry selects that window.

The status line also hosts the prompts: =C-b := (any command), =C-b ,= (rename, starting with the current name), and the =y=/=n= question of =confirm-before= (=C-b x=, =C-b &=). Enter runs, Escape cancels; for a question =y= runs and =n=, Escape or Enter cancel. A command that does not parse, or a refused split, shows its error there for a moment (it is also logged).

** The chooser

=C-b w= (=choose-tree=) opens a list over the panes: every tmux window and, under it, its panes (page title and container colour). =j= / =k= (or the arrows) move, Enter selects the window and pane, =x= kills the selected window or pane, Escape or =q= closes it; a click selects a line.

** Keys

The prefix (=C-b=) sets the window's key grab (=gsurf_window_set_key_grab()=), so the next key reaches wmux even when a page field or the address bar has the focus; that key runs its prefix-table command and clears the grab. An unbound key or Escape cancels the prefix. A *repeatable* key (the arrows, the resize keys, anything listed in =repeatable=) can be pressed again without the prefix for =repeat_time= ms. With =prefix_timeout= set, the prefix gives up after that many milliseconds. A pending prefix (and the =display-panes= numbers, and a repeat window) is also dropped as soon as you click anywhere in the window or the window loses focus, and a pending prefix when another view becomes active, so the grab cannot linger: with the default =prefix_timeout: 0= a stray =C-b= followed by a click into a field would otherwise turn the next typed letter into a wmux command (in this or, after switching back, any later key). The chooser stays open until =Escape= or =q=. The *root table* (=C-h/j/k/l=) works without the prefix, also while typing (modified keys are never typing). =send-prefix= (=C-b C-b=) lets the next prefix press through to the page, for =C-b= (bold) in a web editor.

wmux runs before every other key handler (priority -10, before =modal= and =find_bar=).

** Borders

Every pane frame has the CSS class =wmux-pane=, the active one also =wmux-pane-active=, and a pane whose tab is in a container =wmux-ctr-<container id>=. An inactive pane has a =border_width= border in its container's colour (or =border_color= in the default container, or always with =container_colors: false=) at =inactive_opacity=. The active pane has an =active_border_width= border, in its container's colour mixed toward white by =active_brighten= at full opacity (=active_border_color= in the default container). The stylesheet follows the container registry: a container colour that changes, appears or goes away restyles the panes at once.

** Dragging tabs into panes

With the =tabs= module's sidebar, a tab row can be dragged onto a pane (=mouse: true=, the default). While the drag runs, every pane on screen shows a drop target over its page, and the zone under the pointer is highlighted where the tab would go, in the dragged tab's container colour (=box.wmux-drop-zone=, =active_border_color= for the default container):

| Drop on the pane's  | The tab is shown                         | What the pane showed |
|----------------------+------------------------------------------+----------------------|
| centre               | in that pane, which becomes active       | becomes a background tab; if the dragged tab was in another pane (of any window), the two *swap* (tmux =swap-pane=), so nothing leaves the screen |
| outer 25% of an edge | in a new pane split off on that side (=split_ratio=, the highlight shows its share) | stays; if the dragged tab was in another pane, that pane closes first (tmux =join-pane=; its window closes when it was its only pane) |

Dropping a pane's own tab on its centre selects the pane; on an edge it does nothing. A split that would make a pane smaller than =min_pane_pct= is refused with the usual message. The same operation is available to any chrome through the core seam =gsurf_window_layout_show_view_at(layout, window, view, target, zone)=; =wmux= implements it with these rules.

** Views off screen

A view's web view lives in its pane frame. A tab that no pane of the current tmux window shows keeps its frame, *parked* in the grid: kept, never shown or allocated (=GSURF_WMUX_GRID_PARKED=). This is what the window's own view stack does with hidden tabs, and it keeps every web view realized: reparenting a web view that WebKit is drawing would hand GDK an unrealized widget (a GTK3 WebKit critical) and reload its surface on every switch. A web view leaves its frame only when its tab leaves the window and when wmux is turned off (the window then stacks every view again, all of them alive).

* tmux mapping table

wmux has two binding tables, as tmux does. The *prefix table* holds the keys pressed after the prefix (=C-b= by default). The *root table* holds keys that work without the prefix. Every key is written in canonical notation (see "Key notation") and every command is a line of the command language (see "Command reference"). A *repeatable* key (tmux =bind -r=) can be pressed again without the prefix for =repeat_time= milliseconds after it ran.

** What differs from tmux

- There is no copy mode, no detach, no sessions list and no shell: a pane shows a web page.
- =split-window -c= means "duplicate the current page in the same container", not "start directory".
- =send-prefix= lets the next prefix press through to the page instead of sending it to a program in the pane.
- Arrow keys are repeatable by default (tmux makes only the resize keys repeatable).
- Sizes are percentages of the browser window, not character cells: =resize-pane -L 5= moves a border by 5% of the width, =split-window -p 30= gives the new pane 30% of the old one.
- A command line holds one command; tmux's =\;= command sequences and ={ }= command blocks are not supported.

* Command reference

** Syntax

A command line is one command: its name, then flags, then arguments.

- *Words.* Whitespace (space, tab, newline) separates words.
- *Single quotes* take everything literally up to the next single quote: ='a "b" \c'= is the word =a "b" \c=.
- *Double quotes* allow the escapes =\"=, =\\=, =\n= and =\t=; any other backslash is kept as written: ="a\"b"= is =a"b=.
- *Backslash* outside quotes makes the next character literal: =a\ b= is one word, =a b=.
- *Joining.* Quoted and plain parts next to each other form one word: =a"b c"'d'= is =ab cd=. =""= is an empty word.
- *Control characters* other than the whitespace separators are refused, and the line must be valid UTF-8.
- *Flags* follow getopt: =-hb= is =-h -b=; a flag that takes a value takes the rest of its word or the next word (=-p30= and =-p 30= are equal); =--= ends the flags; the first argument ends them too, so a nested command keeps its own flags (=confirm-before split-window -h=); a lone =-= is an argument.
- *Aliases.* tmux's short names work: =splitw=, =selectp=, =lastp=, =killp=, =resizep=, =swapp=, =rotatew=, =selectl=, =nextl=, =breakp=, =displayp=, =neww=, =next=, =prev=, =last=, =selectw=, =killw=, =renamew=, =confirm=, =lsk=.
- *Placeholders.* =#W= (the current window's name) is kept as written and expanded by the module when the command runs.
- *Canonical form.* Help and =list-keys= print commands in one spelling: the full name, the boolean flags in synopsis order, the valued flags as =-x value=, =--= before an argument that starts with =-=, numbers normalized (=-t +02= prints as =-t +2=), and words quoted only when they need it.

** Errors

A command that does not parse is never run. The error message starts with the byte position of the problem in the line, counting from 0, then says what is wrong:

#+begin_src text
position 14: split-window has no flag -x
position 0: unknown command "spilt-window"
position 16: unterminated single quote
position 0: select-pane needs exactly one of -L, -R, -U, -D, -l, -t
#+end_src

| Error                 | When |
|-----------------------+------|
| no command            | the line is empty or blank |
| syntax                | an unterminated quote, a trailing backslash, a control character, invalid UTF-8 |
| unknown command       | the first word is not a command or alias (names are case-sensitive) |
| unknown flag          | the command has no such flag |
| missing value         | a flag that takes a value ends the line |
| bad value             | a number out of range or not a number, an unknown layout name, a template that is not a command |
| missing argument      | a required flag or argument is absent |
| too many arguments    | more arguments than the command takes; the position is that of the first extra one |
| conflict              | flags that exclude each other (=-h= with =-v=, two directions) |
| too deep              | =confirm-before= and =command-prompt= nested more than 4 levels |

In a nested command the position points into the outer line: in =confirm-before 'split-window -x'= the error is at position 30, the =x=.

** split-window

Synopsis: =split-window [-h|-v] [-b] [-d] [-c] [-p pct] [uri]= (alias =splitw=)

Splits the active pane in two; the new pane shows a new tab.

- =-h= puts the new pane to the right (side by side); =-v= (the default) below.
- =-b= puts the new pane left of or above the active one instead.
- =-d= keeps the active pane active; without it the new pane becomes active.
- =-c= duplicates the current page (same URI, same container) instead of opening a new tab.
- =-p pct= gives the new pane =pct= percent (1 to 99) of the old pane's size; without it the =split_ratio= setting (default 50) applies.
- =uri= opens that address in the new pane.

A split that would make either pane smaller than =min_pane_pct= of the window is refused.

#+begin_example
split-window -h
split-window -v -b
split-window -h -c
split-window -h -p 30 https://github.com
split-window -d -p 25 https://example.org
splitw -hc
#+end_example

Errors: =-h= with =-v= (conflict); =-p= without a value, outside 1..99 or not a number; more than one argument.

** select-pane

Synopsis: =select-pane -L|-R|-U|-D|-l|-t N|+N|-N= (alias =selectp=)

Makes another pane active.

- =-L=, =-R=, =-U=, =-D= select the neighbouring pane in that direction. The candidate that shares the longest edge with the active pane wins; when two share equally much, the one used most recently wins. With nothing in that direction, selection wraps to the far side of the window, like tmux.
- =-l= selects the last (previously active) pane, like =last-pane=.
- =-t N= selects pane number =N= (0 is the first in layout order: left to right, top to bottom); =-t +N= and =-t -N= move =N= panes forward or back in that order, wrapping.

Exactly one of these is required.

#+begin_example
select-pane -L
select-pane -D
select-pane -l
select-pane -t +1
select-pane -t -1
select-pane -t 2
#+end_example

Errors: none or several of the flags (missing argument, conflict); =-t= without a value or not of the form =N=, =+N=, =-N=; any argument.

** last-pane

Synopsis: =last-pane= (alias =lastp=)

Selects the previously active pane in the current window.

#+begin_example
last-pane
#+end_example

Errors: any flag or argument.

** kill-pane

Synopsis: =kill-pane= (alias =killp=)

Closes the active pane. With =on_pane_kill: close_tab= (the default) its tab closes too. The last pane of the last window is never removed: a new blank tab takes its place.

#+begin_example
kill-pane
confirm-before kill-pane
#+end_example

Errors: any flag or argument.

** resize-pane

Synopsis: =resize-pane -L|-R|-U|-D [n] | -Z= (alias =resizep=)

Moves a border of the active pane, or zooms it.

- =-L=, =-R=, =-U=, =-D= move a border in that direction by =n= percent (1 to 100, default 1) of the window width (=-L=, =-R=) or height (=-U=, =-D=). =-R= and =-D= move the pane's right or bottom border; when the pane is the last one in that direction they move its left or top border instead, so the pane shrinks. =-L= and =-U= mirror this. The move stops where any pane on the shrinking side would get smaller than =min_pane_pct=.
- =-Z= zooms the active pane to fill the window, or unzooms. Selecting another pane, splitting, closing, swapping, rotating, resizing and changing the layout all unzoom.

#+begin_example
resize-pane -L
resize-pane -R 5
resize-pane -U 10
resize-pane -Z
#+end_example

Errors: none or several of the flags; =-Z= with an amount; an amount outside 1..100 or not a number; more than one argument.

* Key notation

Every key in the binding tables, in =prefix:= and in the config's =bindings:= and =root_bindings:= has one canonical name, written in tmux notation. A config key may also be written in gsurf notation (as in the core =keybinds:= table); both normalize to the same name. A key press is mapped to the same name, so a binding is a plain lookup.

** Canonical names

- *Modifiers* are =C-= (Control), =M-= (Meta, which is Alt) and =S-= (Shift), always in that order: =C-M-S-Up=.
- *Printable characters* stand for themselves, already shifted: Shift+5 is =%=, Shift+apostrophe is ="=, Shift+a is =A=. Shift never appears on a printable: not =S-5= but =%=, not =C-S-5= but =C-%=, not =S-a= but =A=. Letters with Control keep their case: =C-b= and =C-B= are different keys (the second is Ctrl+Shift+b). Any Unicode character works: =é=, =M-ф=.
- *Named keys* use tmux spellings and keep =S-=: =S-Up=, =C-S-F1=. Shift+Tab is =BTab=.
- *Super is not supported.* The compositor owns it (gowl binds Super), so a config key that names Super (or Hyper) is an error, and a key press with Super held has no wmux name and passes through to gsurf's other bindings and the page.

| Name                           | Key |
|--------------------------------+-----|
| =Space=                        | space bar (also =S-Space=, =C-Space=) |
| =Enter=                        | Return |
| =Escape=                       | Escape |
| =Tab=, =BTab=                  | Tab, Shift+Tab |
| =BSpace=                       | Backspace |
| =Up= =Down= =Left= =Right=     | arrows (the keypad arrows map to these) |
| =Home= =End=                   | Home, End |
| =PPage= =NPage=                | Page Up, Page Down |
| =IC= =DC=                      | Insert, Delete |
| =F1= ... =F12=                 | function keys |
| =KP0= ... =KP9=, =KPEnter=     | keypad digits (NumLock on) and keypad Enter |

Rules for reading a config key:

- Surrounding whitespace is ignored.
- tmux modifiers =C-=, =M-=, =S-= may be written in either case (=s-= is Shift, as in tmux, not Emacs' Super). =^x= is =C-x=.
- gsurf notation is a run of =Word+= modifiers (=Ctrl=, =Control=, =Alt=, =Mod1=, =Meta=, =Shift=; case does not matter) followed by the key. =Super=, =Logo=, =Mod4= and =Hyper= are refused.
- The key is a single character, a tmux name, or a GDK keysym name: =Return=, =BackSpace=, =Page_Up= and the punctuation names (=percent=, =quotedbl=, =apostrophe=, =braceleft=, =period=, =comma=, =semicolon=, =colon=, =question=, =exclam=, =ampersand=, =minus=, =plus=, ...). Names are matched without regard to case.
- Shift is applied to a printable the way a US keyboard does: letters uppercase, the digit row and punctuation shift (=1= =!=, =2= =@=, ..., ='= ="=, =[= ={=), anything already shifted stays.

Errors: an empty key; modifiers without a key (=C-=, =Ctrl+=); an unknown modifier (=Foo+b=); an unknown key name (=F13=, =Nope=); a control character or invalid UTF-8; Super.

** Key presses

A key press is named from its GDK keyval and modifiers:

- The keyval GTK delivers is already shifted (Shift+5 arrives as =percent=), so Shift is dropped from printables: Shift+5 is =%=, Ctrl+Shift+5 is =C-%=, Shift+apostrophe is ="=.
- A press that carries Shift with the unshifted keyval (synthesized input) is shifted as a US keyboard would.
- A letter's case follows Shift, not the keyval, so Caps Lock never turns =c= into =C=.
- Shift stays on named keys: Shift+Up is =S-Up=; Shift+Tab is =BTab=.
- Lock, NumLock, the other Mod bits and the mouse button bits are ignored.
- A press of a modifier key alone (Shift, Control, Alt, Super, Caps Lock, ISO Level3 Shift), a dead key, a media key, or any press with Super held has no name: wmux ignores it.

* Layout string grammar

A tmux window's layout is stored as a compact string, for the session file and for debugging. The model and its parser are =gsurf_wmux_layout_serialize()= and =gsurf_wmux_layout_parse()=.

** Grammar

#+begin_src text
layout  := cell
cell    := pane | split
pane    := "p" id [ "=" payload ]
split   := ( "h" | "v" ) "(" child ( "," child )+ ")"
child   := weight ":" cell
weight  := digits [ "." digit [ digit ] ]
id      := digits                ; 0 .. 4294967294
payload := digits                ; 0 .. 18446744073709551615
#+end_src

- =h= lays its children out side by side, left to right (what =split-window -h= makes); =v= stacks them top to bottom.
- A weight is the child's share of its split, as a percentage with at most two decimals. The writer always produces weights that sum to exactly 100 in each split. The reader takes them as relative and scales them, so =h(1:p0,1:p1,2:p2)= reads as =h(25:p0,25:p1,50:p2)=.
- A pane is =p= and its id. Ids are stable for the pane's life and never reused within a layout; after parsing, the next new pane gets one more than the largest id. The optional payload is an opaque number the module stores per pane: the session module writes the pane's tab index there.
- Whitespace is allowed between tokens.
- Layout order is the order the panes appear in the string; the first pane is active after parsing.

#+begin_src text
p0
h(50:p0,50:p1)
v(50:p0,50:h(50:p1,50:p2))
h(60:p0=0,40:v(33.34:p1=1,33.33:p2=2,33.33:p3=4))
v(50:h(33.34:p0,33.33:p1,33.33:p2),50:h(50:p3,50:p4))
#+end_src

The last one is =tiled= with five panes:

#+begin_src text
+--------+--------+--------+
|   p0   |   p1   |   p2   |
+--------+-----+--+--------+
|      p3      |     p4    |
+--------------+-----------+
#+end_src

** Normal form

The model keeps the tree normalized, and the reader normalizes what it reads:

- a split has at least two children (=h(100:p0)= is an error);
- a split never directly contains a split of the same direction: =h(50:p0,50:h(50:p1,50:p2))= reads as =h(50:p0,25:p1,25:p2)=;
- internally every weight is an integer number of hundredths of a percent, at least 1, and a split's weights sum to exactly 10000, so sizes never drift.

** Geometry

Pane rectangles are computed for any pixel size and gap: each split takes the gaps between its children off its extent, then places child boundaries at the floor of the cumulative weight times the remaining extent. The sizes therefore add up exactly, the last child takes any rounding remainder, and nothing overlaps. When an area is too small for its gaps, the gaps shrink. A zoomed layout gives the zoomed pane the whole area.

** Errors

The reader is strict. An error names the byte position and the problem:

| Input                        | Error |
|------------------------------+-------|
| (empty)                      | =position 0: unexpected end of layout= |
| =x=                          | =position 0: expected 'p', 'h' or 'v'= |
| =h(50:p0)=                   | =position 1: a split needs at least two children= |
| =h(50:p0,50:p0)=             | =position 11: pane p0 appears twice= |
| =h(0:p0,50:p1)=              | =position 2: a weight must be positive= |
| =h(1.234:p0,50:p1)=          | =position 6: a weight has at most two decimals= |
| =h(1:p0,99999:p1)=           | =position 2: weight is too small next to its siblings= |
| =h(50:p0,50:p1) junk=        | =position 15: unexpected text after the layout= |
| =p99999999999=               | =position 1: a pane id is too large= |

Splits nested more than 64 deep are refused.

** Window state

The session module stores all tmux windows of a browser window in one line, built by =gsurf_wmux_state_serialize()= and read by =gsurf_wmux_state_parse()=:

#+begin_src text
state   := ws* "wmux1" ( ws+ header )* ( ws+ window )+ ws*
header  := "current=" index | "last=" index
window  := "[" ws* field ( ws+ field )* ws* "]"
field   := "name=" quoted | "renamed=" ( "0" | "1" )
         | "active=" id | "last=" id | "zoom=" id
         | "layout=" layout
quoted  := '"' ( char | '\"' | '\\' | '\n' | '\t' )* '"'
#+end_src

#+begin_src text
wmux1 current=1 last=0 [name="" renamed=0 active=0 layout=p0=0] [name="docs" renamed=1 active=2 last=1 zoom=2 layout=h(50:p1=1,50:p2=2)]
#+end_src

- =wmux1= is the format version.
- =current= (default 0) and =last= (default none) are window indexes; they must name windows.
- In a window, =layout= is required; =name= defaults to empty and =renamed= to 0. =active= (default the first pane), =last= and =zoom= must name panes of that layout, and =last= must differ from =active=. Fields may come in any order, each at most once.
- The payloads in the layout are the saved tab indexes; a mismatch with the restored tabs is the session module's to handle (it falls back to one pane).
- At least one window is required.

** Drag a tab into a pane

Show the sidebar (=Ctrl+Shift+.=), press a tab row and drag it over the panes: the highlight shows where it goes. Drop it in the middle of a pane to show it there (the tab that was there goes to the background, or swaps places with it when the dragged tab was on screen), or near an edge to split that pane and show it on that side.

#+begin_src yaml
modules:
  wmux:
    enabled: true
    mouse: true              # border drags and tab drops (the default)
  tabs:
    enabled: true
    sidebar: true            # start with the sidebar shown
#+end_src

** The sidebar grouped by window

With both modules on, the sidebar lists each wmux window as a heading (=0:name*=, click to switch to it) with the tabs its panes show and their background children; other background tabs go under a last heading. * Integration

** tabs

The strip and the sidebar list every tab, shown in a pane or not. The sidebar is grouped by wmux window (=tabs.org=, "Grouped by wmux window"): wmux lists its windows through =gsurf_window_layout_list_groups()= (index, the status line's name, current, the tabs its panes show in pane order), selects one through =gsurf_window_layout_select_group()=, and emits =GsurfWindow::layout-groups-changed= whenever that list changes. Sidebar rows can be dragged onto panes (see "Dragging tabs into panes"). Tabs shown in a pane other than the active one carry =gsurf-tab-row-visible= (sidebar) / =gsurf-tab-visible= (strip), coloured by the tabs module's =visible_color=. The tab context menu has *Open in Split Right* and *Open in Split Below* while a layout is installed: they dispatch =pane-split-right= / =pane-split-down= for that tab. wmux handles both: a tab on screen has its pane split with a new tab; a tab off screen (a background tab, or shown in another tmux window) is shown in a new pane split off the active one (it leaves its old pane). The two actions are also core actions (=keybinds:= can bind them; they have no default key). Selecting a tab in the sidebar or the strip follows the rules of "Selecting a tab" above.

** containers

Pane borders take the container's colour (=wmux-ctr-<id>=), live. A new tab from a split goes through the containers module's new-tab policy like =Ctrl+t=; =split-window -c= keeps the current tab's container. Reopening a tab in another container (=container-reopen-next=, the tab menu) keeps its pane: the new view takes the old one's pane before it is activated.

** session

With =remember_layout: true= the session module saves each window's arrangement as an optional =layout:= string in =session.yaml=, next to the window's =tabs= list (see [[file:configuration.org][configuration.org]], Session):

#+begin_src text
windows:
  - active: 1
    layout: "wmux1 current=0 last=1 [name=\"\" renamed=0 active=1 layout=h(50:p0=0,50:p1=1)] [name=\"docs\" renamed=1 active=0 layout=p0=2]"
    tabs:
      - uri: https://github.com/
      - uri: https://example.org/
      - uri: https://docs.example.org/
#+end_src

- *Saving.* The string is the window state of "Window state" above (=gsurf_window_layout_serialize()=): every tmux window, its name, its layout with the active, last and zoomed panes, the current and last window. Each pane's payload is the *saved index* of its tab: its position in that window's =tabs= list, the numbering =active= and =parent= use. A tab the session does not save (blank, =about:blank=) has no index, so its pane is left out of the saved layout (a tmux window left without panes is left out too). The session module saves whenever the arrangement changes (wmux announces every split, close, zoom, resize, rename and window switch with =GsurfWindow::visible-views-changed=). With =remember_layout: false= no =layout:= is written.
- *Restoring.* wmux activates before the session module (priority -10), so its layout is installed when the session restores the tabs. Once every tab exists and the active tab is set, the session hands the string and the restored views (=views[i]= for saved index =i=, =NULL= for a tab that could not be restored) to =gsurf_window_layout_restore()=. wmux rebuilds the tmux windows only if every pane names a distinct restored tab; the views no pane names become background tabs, and the current window's active pane becomes the active tab.
- *Mismatch.* If a pane names a tab that is missing (the file was edited, a tab had no =uri=), or the string does not parse, wmux refuses it and keeps its default arrangement (one tmux window, one pane with the active tab); the session module logs a warning. Only the first saved window's layout is used (gsurf runs one window per process).

** modal

=o= (=open-prompt=) and the hint keys work on the active pane; =gt= / =gT= select tabs by the rules above. wmux's keys run before modal's (priority -10), so the prefix and =C-h/j/k/l= win, also in modal's insert mode (the key grab and modified keys pass the typing guard).

** chromebar

The address bar shows and edits the active pane's address; Enter loads into the active pane. With the default root table =C-l= moves to the right pane instead of focusing the address bar.

** Kiosk mode and libregnum

Kiosk mode shows a single view by design, and the libregnum (=--lrg=) window cannot host a layout. In both wmux stays inactive and says so once (=g_message=); the window keeps its plain view stack and every other module works as usual.

* C config

The same setup in =~/.config/gsurf/config.c= (see [[file:c-config.org][c-config.org]]): module options are read from the YAML =modules:= mapping, so a C config layers them in with =gsurf_config_load_from_data()=. The loader replaces the =modules:= mapping, so give the complete block (every module you use).

#+begin_src c
#include <gsurf/gsurf.h>

static const char *MODULES_YAML =
"modules:\n"
"  tabs:\n"
"    enabled: true\n"
"  wmux:\n"
"    enabled: true\n"
"    prefix: \"C-a\"\n"
"    status_position: top\n"
"    bindings:\n"
"      \"|\": \"split-window -h\"\n"
"      \"-\": \"split-window -v\"\n"
"    root_bindings:\n"
"      \"C-l\": \"\"\n"
"      \"M-l\": \"select-pane -R\"\n";

G_MODULE_EXPORT gboolean
gsurf_config_init(void)
{
	GsurfConfig *config = gsurf_config_get_default();

	if (config == NULL)
		return FALSE;
	/* Core settings as usual, then the module block. */
	gsurf_config_load_from_data(config, MODULES_YAML, -1, NULL);
	return TRUE;
}
#+end_src

* Limits and troubleshooting

- *Off-screen tabs stay realized.* A tab that no pane shows keeps its web view, hidden, in the grid, exactly as the window's view stack keeps hidden tabs. Nothing reloads or flashes when you switch tmux windows or tabs. The first time a tab is shown in a pane its web view moves into the pane (a tab created in the background was never drawn before).
- *Some sites grab keys.* wmux sees a key before the page does, and the prefix sets the window's key grab, so the key after it always reaches wmux. A bare key without the prefix while a page field has focus belongs to the page. Sites that capture modified keys (=C-h= in some editors) cannot have them while the root table binds them; unbind them in =root_bindings= or move navigation to =M-h/j/k/l= (cookbook).
- *=C-b= in a web editor* (bold) needs =send-prefix=: =C-b C-b= sends one =C-b= to the page. With another prefix the same goes for it.
- *=C-l= does not open the address bar* while the root table binds it: use =o= (modal), or the cookbook's Alt-key navigation.
- *Super is not a wmux modifier*: the compositor owns it.
- *Commands are one per line*: tmux's =\;= sequences and ={ }= blocks do not exist; there is no copy mode, detach or shell.
- *Where warnings go*: configuration problems are =g_warning=, command errors and refused splits are =g_message= (and shown in the status line), restore mismatches are =g_debug= (the session module warns). gsurf logs to stderr; run =G_MESSAGES_DEBUG=all gsurf= to see the debug lines.
- *Kiosk and =--lrg=*: wmux stays off (logged once).
