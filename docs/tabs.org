#+TITLE: Tabs: strip and tree sidebar
#+OPTIONS: toc:2 num:nil

* Overview

The =tabs= module gives a window two views of its tabs, on GTK3 and GTK4 alike:

- the *strip*: a row of flat tab buttons above (or below) the page, in window order;
- the *tree sidebar*: a Sidebery-style vertical list beside the page, where each tab sits under the tab it was opened from. With the =wmux= module the sidebar is grouped by wmux window (see "Grouped by wmux window"), and tabs can be dragged from it into panes.

It also owns the keyboard tab commands (new, close, next, previous, reopen) and the tree commands (toggle the sidebar, collapse a subtree, move a subtree up or down). The sidebar starts hidden; =Ctrl+Shift+.= shows it.

The module is three parts built into one =tabs.so=:

| File                              | Role |
|-----------------------------------+------|
| =modules/tabs/gsurf-tab-tree.c=   | The toolkit-neutral tree model. It knows view ids and openers, not GTK or =GsurfView=. |
| =modules/tabs/gsurf-tabs-module.c= | The module core: configuration, keys, actions, window and view signals; keeps the model and the window's view order in step. |
| =modules/tabs/gsurf-tabs-ui.c=    | The strip and the sidebar. All toolkit calls go through =modules/include/gsurf-chrome-compat.h=, so one file serves both GTK versions. |

* The tree

** Where the tree comes from

The window's view order is the source of truth; the tree is derived from it. Every view records its opener at construction (=gsurf_view_new_full()=; see "Opened from a tab" for every path that sets one). =gsurf_view_get_opener_id()= keeps that id after the opener closes. A view opened by the user (=tab-new=, startup, the MCP =open= tool) has no opener.

Each tab has a /logical parent/, initially its opener. The tree is built by walking the window order with a stack holding the path from a root to the previous tab:

1. If the tab's logical parent is on the stack, pop down to it; the tab becomes its child.
2. Otherwise the tab is a root, and the stack restarts with it.

So a tab keeps its parent only while the parent comes earlier in the window and the tab directly continues the parent's block of descendants. Every subtree is therefore one contiguous run of tabs, and the sidebar is the window order with indentation. After each change the logical parents are set to the derived ones, so a tab that once lost its parent never silently re-attaches to it later.

** Placement of new tabs

When a view is added to the window:

- if its opener is in the same window, the view is moved (=gsurf_window_move_view()=) to just after the opener's *last descendant*, making it the opener's last child;
- otherwise (no opener, or an opener in another window or already closed) it stays where the window put it, which is the end for =gsurf_window_add_view()=; it is a root.

Opening three links from tab A in turn gives =A, A1, A2, A3=, and a link opened from =A1= goes between =A1= and =A2=.

=tab-new= and =tab-reopen= create their view with the URL they are about to load as its container placement hint (=gsurf_view_new_full()=), so with the =containers= module a reopened tab for an assigned host comes back directly in that container instead of being moved after its first request.

** Closing a tab

=on_close_parent= decides what happens to the children of a closing tab:

- =promote= (default): each direct child takes the closed tab's place in the tree, moving up one level (to the closed tab's parent, or to the root). The children keep their order and their own subtrees, and stay where they are in the window.
- =close_children=: the closed tab's descendants close with it (and are remembered for =tab-reopen=, most recent first). The module never closes a window's last view: if the descendants are all that would remain, the last one stays open as a root.

This applies however the tab closes: the close key or button, a middle click, the page calling =window.close()=, or another module.

** Orphans

A tab whose opener is closed, or never was in this window, is a root. Its opener id is kept (=gsurf_view_get_opener_id()= never changes), but the tree does not use it once the opener is gone. A promotion is runtime state: when the module is reactivated, or a session is restored, the tree is rebuilt from the window order and the openers alone, so a promoted tab whose opener is closed comes back as a root. A restored session that recreates its views in order with their openers (=gsurf_view_new_full()=) gets the same tree back.

** Collapse

A tab with children shows a twisty (=▾= expanded, =▸= collapsed). Collapsing it hides its descendants in the sidebar; they stay open and keep loading. Collapse state belongs to the tab and survives reorders.

- Clicking the twisty, or =tab-tree-collapse= on a tab with children, toggles its subtree.
- =tab-tree-collapse= on a leaf collapses the leaf's parent.
- Collapsing a subtree that holds the active tab makes the collapsed tab active, so the active tab is always visible.
- Activating a hidden tab by any means (=tab-next=, the strip, the host) expands all its collapsed ancestors.

** Opened from a tab

Every way of opening a page from a tab makes the new tab that tab's child, placed as its last child (Sidebery style):

| How                                         | New tab is                    | Notes |
|---------------------------------------------+-------------------------------+-------|
| Middle click or =Ctrl+click= on a link      | a background child (default)  | The default mousebinds map =Button2= and =Ctrl+Button1= to =open-new-view-background=; bind them to =open-new-view= for a foreground child. Off a link the click is the engine's (paste, autoscroll). |
| Page context menu: "Open Link in New Tab"   | a background child            | Replaces WebKit's "Open Link in New Window": gsurf runs one window per process, so that item only opened a popup tab sharing the page's session. The host opens the tab through =GsurfView::new-view-requested= (=gsurf_view_request_new_view()=); a host that does not connect it (an embedder) keeps WebKit's item. |
| =target=_blank=, =window.open()=            | a foreground child, related   | A popup (=GsurfView::create-view=): it shares the page's web process and session so =window.opener= works, and it stays in the page's container. |
| =modal= =F= link hints                      | a foreground child            | |
| =Duplicate Tab= (context menu)              | a foreground child            | Same container. |
| A tab moved to its host rule's container    | the same place                | The =containers= module replaces a tab whose first load lands on another container's host (=gsurf_window_replace_view()=): the new tab keeps the old one's place, parent (even one already closed: =GsurfView:opener-id=), children, collapse state, pane, and whether it was the active tab, so a background child stays a background child. |

With a window layout (=wmux=), a background child is a background tab: it does not take a pane, and the grouped sidebar shows it under its parent's pane tab. A foreground child is shown in the active pane, like any activated tab.

** Moving subtrees

=tab-move-up= and =tab-move-down= move the active tab together with its whole subtree past the previous or next *sibling* (and that sibling's subtree). A tab never changes parent this way; at its first or last sibling the command does nothing. The window's view order is updated to match.

When something else reorders the window (=gsurf_window_move_view()= from another module or the MCP interface), the tree is re-derived from the new order. A tab moved out of its parent's block becomes a root.

** Depth cap

=max_depth= caps the indentation: a tab deeper than =max_depth= is drawn at =max_depth= levels but keeps its real parent, so collapsing, closing and moving still follow the real tree. =max_depth: 0= draws a flat list.

* The sidebar

The sidebar is packed beside the page with =gsurf_window_add_side_widget()=, on the left or right (=sidebar_position=), =sidebar_width= pixels wide; it keeps exactly that width on GTK3 and GTK4 and the page gets the rest of the window. It is not resizable by dragging. =tab-sidebar-toggle= (default =Ctrl+Shift+.=, which GDK reports as =Ctrl+Shift+greater=) shows and hides it; =sidebar:= sets the state at startup. While it is shown, =sidebar_hides_strip: true= hides the strip.

Each row shows, left to right:

- a 3px container stripe (see below);
- the twisty, empty and insensitive when the tab has no children;
- the favicon (=gsurf_view_get_favicon()=: a =cairo_surface_t= on GTK3, scaled to 16px; a =GdkTexture= on GTK4), updated on =favicon-changed=;
- the title (or the URI, or "New Tab"), ellipsized, updated on =title-changed=;
- a close button.

The row is indented by =indent= pixels per level and the active tab is highlighted with =active_color=; a tab on screen in another pane gets =visible_color= (see "Tabs in panes"). A primary click (pressed and released without dragging) activates its tab; a middle click closes it; a right click opens its context menu (see "Context menu" below). Clicks on the twisty and close buttons stay with those buttons. Pressing and dragging a row starts a drag (see "Drag and drop").

Rows are kept and updated in place: adding, closing or moving a tab creates, removes or reorders one row, and each row only re-applies the properties (indentation, twisty, visibility, highlight, the in-pane style) that changed. The strip is simply rebuilt.

** Drag and drop

Each tab row is a drag source for a private, same-application target (=application/x-gsurf-view-id=, =GSURF_LAYOUT_VIEW_MIME_TYPE=, the view id as text) and a drop target for it:

- *Onto another row*: the upper quarter of the row puts the dragged tab (with its subtree) right *before* that tab, as its sibling; the lower quarter puts it *after* that tab's whole subtree, as its sibling; the middle makes it that tab's *last child*. The row under the pointer shows where with a line above or below it, or a frame around it (CSS classes =gsurf-tab-drop-before=, =-after=, =-child=, in =fg_color=). A tab cannot be dropped on itself or into its own subtree (the drop is refused while hovering). The window's view order follows (=gsurf_tab_tree_move_to()=, then the order is applied with =gsurf_window_move_view()=). Group headings (see below) are no drop targets.
- *Onto a pane* of a window layout: while a drag runs, the module tells the layout (=gsurf_window_layout_begin_view_drag()= / =_end_view_drag()=), and the layout takes drops on its own widgets; =wmux= shows the tab in a pane or splits one (=wmux.org=, "Dragging tabs into panes").

Because a press may start a drag, the primary click acts on release; a drag never activates the tab. Both toolkits share the code through the compat header's DnD helpers (see "GTK3 and GTK4").

** Grouped by wmux window

When the window's layout has groups (=gsurf_window_layout_list_groups()=; =wmux='s windows) and =wmux_groups= is on (the default), the sidebar is grouped by them instead of being one opener tree:

1. One *heading* per wmux window, in window order, labelled like wmux's status line: =<index>:<name>=, with =*= after the current window (=0:github*=), which also gets the =gsurf-tab-group-current= class (=visible_color=). Clicking a heading selects that window (=gsurf_window_layout_select_group()=).
2. Under it, the tabs its panes show, in pane order (left to right, top to bottom), each with its container stripe and the usual active / in-pane styles.
3. Under each pane tab, its descendants in the opener tree that no pane shows (background tabs), nested as in the tree. A descendant that is shown in a pane is listed under its own pane instead, with its subtree.
4. A final heading, =background_label= (default =Background=), for the background tabs that descend from no pane tab, nested as in the tree. It is left out when there are none; clicking it collapses or expands it.

Headings have a twisty: collapsing one hides its group (the collapse state is per window index and lasts until the module is reactivated). A tab row's twisty collapses its nested rows as in the plain tree. The headings follow =GsurfWindow::layout-groups-changed=, which wmux emits when a window is created, killed, renamed or selected, when a pane shows another tab, and when an automatically named window's active page changes title.

Without a layout, with a layout that has no groups, or with =wmux_groups: false=, the sidebar is the plain opener tree exactly as described above; it switches back the moment wmux is deactivated (the window emits =layout-groups-changed= when a layout is removed). The strip stays flat in every case. The underlying tree (order, parents, collapse state) does not change when the sidebar regroups, so sessions save and restore it as before.

** Tabs in panes

When a window layout is installed (=gsurf_window_set_layout()=, normally by the =wmux= module), several tabs can be on screen at once, one per pane. The module asks the window which tabs are on screen (=gsurf_window_get_view_visible()=) and follows =GsurfWindow::visible-views-changed=, which the layout emits whenever a split, a closed pane or a different tab in a pane changes that set. A tab that is on screen but is not the active tab gets the CSS class =gsurf-tab-row-visible= on its sidebar row and =gsurf-tab-visible= on its strip tab, styled with a =visible_color= background: subtler than the active tab, which keeps =gsurf-tab-row-active= / =gsurf-tab-active= only (the focused pane). Tabs in no pane (background tabs) look as before. Without a layout only the active tab is on screen, so nothing changes visually. The handler is connected and disconnected with the other window handlers.

** Container stripes

A tab in a container (=gsurf_view_get_container_id()=, see =GsurfContainerRegistry=) gets a coloured stripe, a tooltip naming the container on the stripe, and "Container: <name>" in the row's tooltip. Tabs in the default container show none. The colour is the container's =color= (=fg_color= when it has none). The module follows the registry: =container-added= and =container-removed=, and each container's =notify::color= and =notify::name=, restyle and retitle the rows at once. Container colours pass through =GdkRGBA= before they reach the stylesheet, and only ids made of letters, digits, =-= and =_= become CSS classes (=gsurf-ctr-<id>=).

** Context menu

A right click on a sidebar row or a strip tab opens that tab's menu (a =GtkPopoverMenu= on GTK4, a =GtkMenu= on GTK3), in the style of Sidebery. It is built each time it opens, so it only offers what applies to that tab:

| Entry                 | Shown when                | What it does |
|-----------------------+---------------------------+--------------|
| Reload Tab            | always                    | Reloads the tab (=gsurf_view_reload()=, cache not bypassed). |
| Duplicate Tab         | always                    | Opens the tab's page in a new tab, as its child (right under it in the tree), in the same container, and activates it. |
| Open in Split Right   | the window has a layout   | Dispatches the =pane-split-right= action with this tab's view (=gsurf_module_manager_dispatch_action()=). The module owning the panes (=wmux=) splits the tab's pane when it is on screen, else shows the tab in a new pane on the right. |
| Open in Split Below   | the window has a layout   | The same with =pane-split-down=: the new pane below. |
| Reopen in Container ▸ | containers are in use     | A submenu: =Default=, each persistent container in config order, and =New Temporary Container=. The tab's current container is the checked item. Picking one reopens the tab there (below). |
| Collapse / Expand Tree | the tab has children     | Collapses or expands its subtree, like the twisty. |
| Close Children        | the tab has children      | Closes its whole subtree and keeps the tab. |
| Close Tab             | always (disabled on the last tab) | Closes the tab, like its close button. |

"Containers are in use" means a placement policy is installed in the container registry (=gsurf_container_registry_has_resolver()=), i.e. the =containers= module is enabled. With it disabled the submenu is left out; the other entries work the same. "The window has a layout" means =gsurf_window_get_layout()= is not =NULL= (the =wmux= module is enabled); without one the split entries are left out. Kiosk mode shows no strip or sidebar, so no menu at all (and refuses layouts anyway).

*Reopening in a container* goes through =gsurf_window_reopen_view()=: WebKit fixes a tab's session when it is created, so a new tab is created in the chosen container with the old tab's opener, put at its place, made active and loaded with its URI, and then the old tab is removed. The window emits =view-replaced (old, new)= right after adding the new tab and before activating it, and the module hands the old tab's place in the tree to the new one: same position, same parent, its children stay its children and its collapse state is kept, whatever =on_close_parent= says. =container-reopen-next= (=Ctrl+Alt+c=, the =containers= module) uses the same function, so it keeps the children too. The reopened page loads in the new container's jar: its cookies and storage, not the old ones. History (back/forward) does not carry over.

The menu acts on the tab that was right-clicked, not on the active tab, and does nothing if that tab closed in the meantime. Its actions live in an action group inserted as =tab= on the strip and on the sidebar (=tab.reload=, =tab.duplicate=, =tab.split-right=, =tab.split-down=, =tab.container= with a string target, =tab.toggle-collapse=, =tab.close-children=, =tab.close=). The menu hangs off the strip or the sidebar and is positioned against the toplevel window, never against the tab's own widget, so reopening or closing the tab from the menu cannot leave the menu anchored to a destroyed widget (GTK3 on Wayland repositions popups against their anchor window).

* The strip

The strip shows one flat button per tab in window order (titles cut to 24 characters) with a close button; the active tab uses =active_color=. Clicking a tab activates it; a right click opens its context menu (see "Context menu"). It is shown when the window has more than one tab, or always with =show_single: true=, unless the sidebar is shown and =sidebar_hides_strip= is set. =strip: false= turns the strip off entirely, for a sidebar-only setup: the sidebar toggle then switches between the tree and no tab chrome at all, and the keyboard keys (=Ctrl+Tab= and friends) keep working.

Rules:

- Colours are CSS colours as =GdkRGBA= parses them (=#rrggbb=, =rgb()=, names, ...). An invalid colour logs a warning and keeps the default, so nothing malformed reaches the stylesheet.
- An out-of-range or non-numeric width, indent or depth, or an unknown =position=, =sidebar_position= or =on_close_parent=, logs a warning naming the key and keeps the default. The rest of the block still applies.
- An empty key (=key_collapse: ""=) unbinds it; the action stays available through the core =keybinds:= table.
- Each =configure()= starts from the defaults, so a second call replaces the configuration entirely (a key left out returns to its default). Layout options (=position=, =sidebar_*=, colours) take effect at the next activation; the keys and =on_close_parent= apply at once, and =indent= and =max_depth= with the next change to the tabs.

* Keys and actions

The module matches its own keys (=GsurfInputHandler=) and performs the same actions when the core =keybinds:= table forwards them (=GsurfActionHandler=), so =tab-sidebar-toggle= and friends can also be bound there. All its keys are listed in the =?= overlay (=GsurfKeybindProvider=).

| Action               | Default key              | Effect |
|----------------------+--------------------------+--------|
| =tab-new=            | =Ctrl+t=                 | Open =new_view_uri= in a new root tab. |
| =tab-close=          | =Ctrl+w=                 | Close the active tab (never the last one). |
| =tab-next= / =tab-prev= | =Ctrl+Tab= / =Ctrl+Shift+Tab= | Cycle through the window order, hidden tabs included (activating one expands its ancestors). |
| =tab-reopen=         | =Ctrl+Shift+t=           | Reopen the most recently closed URI. |
| =tab-sidebar-toggle= | =Ctrl+Shift+.=           | Show or hide the sidebar. |
| =tab-tree-collapse=  | =Ctrl+Shift+[=           | Collapse or expand the active tab's subtree (on a leaf: its parent's). |
| =tab-move-up=        | =Ctrl+Shift+Page_Up=     | Move the active tab and its subtree above its previous sibling. |
| =tab-move-down=      | =Ctrl+Shift+Page_Down=   | Move the active tab and its subtree below its next sibling. |

*Conflict check.* The four tree keys are not used by the core table or by any other module's defaults in =data/default-config.yaml=, so they were kept as planned. The existing overlap of =key_reopen= (=Ctrl+Shift+t=) with =toggles= =strict_tls= is unchanged: the module that sees the key first (by priority) takes it.

*Kiosk.* In kiosk mode the module shows neither strip nor sidebar; =tab-new= and =tab-reopen= are refused, and the tree actions do nothing visible.

* Lifetime

The module follows the chrome module rules (=docs/modules.org=, "Chrome module lifetime"):

- Deactivation and disposal disconnect every handler (window, views, container registry, containers, rows, strip buttons), close and drop the context menu and its action group, detach the strip and sidebar, remove the stylesheet and free the tree. Both are idempotent, and =activate()= after =deactivate()= builds exactly one strip and one sidebar.
- The strip, the sidebar, its list and every row are retained by the module until cleanup, so the host destroying the window chrome first leaves no dangling pointers. The module holds a weak reference on the window and releases everything when the window finalizes first.
