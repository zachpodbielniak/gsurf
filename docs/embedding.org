#+TITLE: Embedding gsurf
#+OPTIONS: toc:2 num:nil

* libgsurf

gsurf is library-first: link =libgsurf.so= and use its GObject API. A
=gsurf.pc= pkg-config file is installed.

#+begin_src sh
pkg-config --cflags --libs gsurf
#+end_src

* Minimal embed

#+begin_src c
#include <gsurf/gsurf.h>

int main(int argc, char **argv)
{
    gsurf_init(&argc, &argv);
    gsurf_backend_init(&argc, &argv, NULL);

    GsurfConfig *config = gsurf_config_new();
    GsurfApplication *app = gsurf_application_new(config);

    GsurfWindow *window = gsurf_window_new();   /* compiled-in backend */
    GsurfView   *view   = gsurf_view_new();
    gsurf_window_add_view(window, view);
    gsurf_application_add_window(app, window);

    gsurf_view_load_uri(view, "https://example.com");
    gsurf_window_present(window);

    gsurf_application_run(app);   /* or drive your own GLib main loop */
    return 0;
}
#+end_src

* Loading modules (host-controlled)

The library never loads modules on its own. A host decides *where* modules come
from by configuring the module manager's search path and then asking it to load:

#+begin_src c
GsurfModuleManager *mgr = gsurf_module_manager_get_default();
gsurf_module_manager_set_application(mgr, app);
gsurf_module_manager_set_config(mgr, config);

/* Point at the embedding application's OWN module directory only. */
gsurf_module_manager_add_search_path(mgr, "/opt/cmacs/lib/gsurf/modules");
gsurf_module_manager_load_modules(mgr);          /* loads *.so from each path */

gsurf_module_manager_activate_all(mgr);          /* after window/view exist */
#+end_src

This is the isolation an embedder (e.g. cmacs) wants: an embedded gsurf loads
=*only*= the modules the host points it at. The =GSURF_MODULE_PATH= environment
variable and the built-in system module directory are =never= consulted
automatically — that env/exe/system fallback is the standalone =gsurf= binary's
own policy (in its =main.c=), not the library's. So an embedded gsurf will not
pick up a system-installed gsurf's modules, even if one is installed.

Useful calls (see =gsurf-module-manager.h=):

- =gsurf_module_manager_add_search_path()= — append a directory (deduped, ordered).
- =gsurf_module_manager_set_search_paths()= — replace the whole list (or clear with %NULL).
- =gsurf_module_manager_clear_search_paths()= — empty the list.
- =gsurf_module_manager_get_search_paths()= — inspect the current list.
- =gsurf_module_manager_load_modules()= — load =*.so= from every path, first-match
  by file name wins (like =$PATH=).
- =gsurf_module_manager_get_system_module_dir()= — the compile-time system dir,
  returned for hosts that want to opt in to system modules by adding it explicitly.

* Embedding the widget in another GTK app

=gsurf_view_get_native_widget()= / =gsurf_window_get_native_widget()= return the
underlying =GtkWidget*= as an opaque =gpointer= so the abstract API never leaks a
GTK type. A GTK-aware host casts it and packs it into its own container instead
of calling =gsurf_window_present()=. With the webkit2gtk-4.1 backend the
returned widget *is* the =WebKitWebView=, so a host can reach the WebKit layer
directly (e.g. =webkit_web_view_get_context()=, =..._get_user_content_manager()=)
to add features that the abstract API does not wrap.

* View signals a host can observe

A =GsurfView= emits these GObject signals; a host that parents the raw view
(no =GsurfWindow=) connects to them for chrome/automation:

- =load-changed= =(GsurfLoadEvent)=, =uri-changed= =(uri)=, =title-changed= =(title)=
- =progress-changed= =(gdouble 0..1)=, =hovered-uri-changed= =(uri or "")=
- =favicon-changed= =()= (read it with =gsurf_view_get_favicon()=: a =cairo_surface_t*= on GTK3, a =GdkTexture*= on GTK4), =web-process-terminated= =()=
- =script-message::<name>= =(name, json)= — a message posted to a handler registered with =gsurf_view_register_script_message()=
- =new-view-requested= =(uri, background) -> gboolean= (since 0.4.2) — the page context menu's "Open Link in New Tab" (=gsurf_view_request_new_view()=): open =uri= in a new, unrelated view whose opener is the source (=gsurf_view_new_full(source, NULL, uri, FALSE)=), leaving the source active when =background= is =TRUE=, and return =TRUE=. Only while a handler is connected does the menu replace WebKit's "Open Link in New Window" with that item (=gsurf_view_has_new_view_handler()=).
- =create-view= =(uri) -> GsurfView*= — a popup / =target=_blank= / =window.open=
  request. The handler returns a *new, unrealized* =GsurfView= for WebKit to
  take over, or =NULL= to block the popup. The return is =(transfer none)=, and
  it uses a first-handler-wins accumulator. A host that has no spare unrealized
  view should return =NULL= and open the URI itself instead — returning a view
  that is already realized/parented fights WebKit's popup lifecycle.
  Build the popup as a *related* view of the source:
  =gsurf_view_new_full(source, NULL, uri, TRUE)=. WebKit requires a popup to
  share its opener's session, and the related view lands in the opener's
  container and keeps =window.opener= working; =gsurf_view_get_opener()= then
  links the two (a tab tree or buffer tree can use it).

Views also carry an identity for hosts that keep their own list (cmacs keeps one per buffer): =gsurf_view_get_id()= (stable, never reused; =gsurf_view_lookup()= maps it back), =gsurf_view_get_opener()= / =gsurf_view_get_opener_id()=, and =gsurf_view_get_container_id()= with =gsurf_container_registry_lookup()= for the container's name and colour. A host that creates views itself should pass the opener (and, if it wants, a container id) to =gsurf_view_new_full()=. To move a page to another container, =gsurf_window_reopen_view()= does the whole replacement on a =GsurfWindow=; a host with its own view list (one buffer per view) should instead create the new view with =gsurf_view_new_full(gsurf_view_get_opener(old), container_id, uri, FALSE)= and swap it into the buffer itself. =gsurf_container_registry_has_resolver()= says whether a container policy (the =containers= module) is installed, i.e. whether offering container choices makes sense.

* Downloads and permissions (host dispatch)

These are answered *synchronously*, so a host hook must decide without blocking:

- *Downloads*: the backend connects =download-started= on the WebKit context and
  dispatches =decide-destination= to a =GsurfDownloadHandler= module
  (=(uri, suggested) -> path=, first non-NULL wins; return without a path to let
  the engine default). gsurf tracks no further progress itself — a host that
  wants progress/finished/failed events listens on the WebKit download directly
  (via the default =WebKitWebContext=).
- *Permissions*: the backend dispatches =permission-request= to a
  =GsurfPermissionHandler= module expecting a synchronous verdict
  (=ALLOW=/=DENY=/=PROMPT=); =PROMPT= returns =FALSE= so the engine default
  applies, which also lets a host that connects its *own* =permission-request=
  handler on the =WebKitWebView= (and returns =TRUE=) win when no gsurf
  permission module is enabled. A blocking modal inside this callback is unsafe;
  decide from a policy, or defer by reffing the request and answering later.

* Arranging views: window layouts

A host that wants several views on screen in one =GsurfWindow= (panes, a grid, a carousel) implements =GsurfWindowLayout= and installs it with =gsurf_window_set_layout()=; see "Window layouts (panes)" in =architecture.org= for the full contract and call order. The layout owns its root widget and decides where each view widget goes; the window keeps the view list, the active view and every signal, so modules (tabs, chromebar, session) keep working. cmacs could implement it to put several gsurf views in one frame without giving up the window's bookkeeping.

The minimal useful layout shows two views side by side (GTK4 shown; GTK3 uses =gtk_box_pack_start()= / =gtk_container_remove()=). =tests/test-window-layout-webkit.c= has the same layout for both toolkits.

#+begin_src c
typedef struct { GObject parent; GtkWidget *box; } PairLayout;
typedef struct { GObjectClass parent; } PairLayoutClass;
static void pair_iface_init(GsurfWindowLayoutInterface *iface);
G_DEFINE_TYPE_WITH_CODE(PairLayout, pair_layout, G_TYPE_OBJECT,
	G_IMPLEMENT_INTERFACE(GSURF_TYPE_WINDOW_LAYOUT, pair_iface_init))

static gpointer pair_root(GsurfWindowLayout *l) { return ((PairLayout *)l)->box; }

static void
drop(GtkWidget *box, GtkWidget *w)
{
	if (gtk_widget_get_parent(w) == box)
		gtk_box_remove(GTK_BOX(box), w);
}

static void
pair_add(GsurfWindowLayout *l, GsurfWindow *window, GsurfView *view)
{
	GtkWidget *box = ((PairLayout *)l)->box;
	GtkWidget *w = gsurf_view_get_native_widget(view);

	/* Two panes; any further view stays an unparented background view. */
	if (gtk_widget_get_first_child(box) == gtk_widget_get_last_child(box)) {
		gtk_widget_set_hexpand(w, TRUE);
		gtk_box_append(GTK_BOX(box), w);
	}
}

static void
pair_remove(GsurfWindowLayout *l, GsurfWindow *window, GsurfView *view)
{
	drop(((PairLayout *)l)->box, gsurf_view_get_native_widget(view));
	gsurf_window_layout_notify_visible(window);
}

static void
pair_activate(GsurfWindowLayout *l, GsurfWindow *window, GsurfView *view)
{
	/* A background view would be swapped into a pane here. */
	gsurf_view_focus(view);
}

static void
pair_detach(GsurfWindowLayout *l, GsurfWindow *window)
{
	GPtrArray *views = gsurf_window_get_views(window);

	for (guint i = 0; i < views->len; i++)
		drop(((PairLayout *)l)->box,
		     gsurf_view_get_native_widget(g_ptr_array_index(views, i)));
}

static gboolean
pair_visible(GsurfWindowLayout *l, GsurfWindow *window, GsurfView *view)
{
	return gtk_widget_get_parent(gsurf_view_get_native_widget(view)) ==
	       ((PairLayout *)l)->box;
}

static void
pair_iface_init(GsurfWindowLayoutInterface *iface)
{
	iface->get_root = pair_root;
	iface->detach = pair_detach;
	iface->add_view = pair_add;
	iface->remove_view = pair_remove;
	iface->activate_view = pair_activate;
	iface->is_view_visible = pair_visible;
}

static void pair_layout_class_init(PairLayoutClass *klass) { }

static void
pair_layout_init(PairLayout *self)
{
	/* The layout keeps its own reference: the window only packs it. */
	self->box = g_object_ref_sink(gtk_box_new(GTK_ORIENTATION_HORIZONTAL, 0));
	gtk_box_set_homogeneous(GTK_BOX(self->box), TRUE);
}

/* ... */
PairLayout *layout = g_object_new(pair_layout_get_type(), NULL);
if (!gsurf_window_set_layout(window, GSURF_WINDOW_LAYOUT(layout)))
	;   /* kiosk mode, or the libregnum backend: one view at a time */
g_object_unref(layout);                        /* the window holds it */
/* later: gsurf_window_set_layout(window, NULL) restores the stack */
#+end_src

Rules worth knowing:

- Views keep their own reference to their widget, so a layout may unparent a view widget freely; WebKit unrealizes a widget that is unparented, which can flash.
- =add_view= must not focus; =activate_view= must (the window does not focus the view itself while a layout is set). Focus into a visible view makes it active (focus follows click); a background view never becomes active that way.
- Call =gsurf_window_layout_notify_visible()= whenever the views on screen change, so chrome can follow (=visible-views-changed=).
- =gsurf_window_set_key_grab()= lets a host or module see the next key even while the user types in a page field or the address bar, e.g. after a prefix key.
- Optional (since 0.4.2): a layout with several arrangements implements =list_groups= / =select_group= and calls =gsurf_window_layout_notify_groups()= when they change, so the =tabs= sidebar groups its tree by them; one that accepts views dragged from chrome implements =show_view_at= and =begin_view_drag= / =end_view_drag= (show drop targets for =GSURF_LAYOUT_VIEW_MIME_TYPE= over its views while a drag runs). See "Groups and drops" in =architecture.org=.

* Runtime directory and working directory

libgsurf keeps per-process scratch data in =$XDG_RUNTIME_DIR/gsurf/<pid>-XXXXXX= (see =gsurf-runtime-dir.h=): temporary containers store their profiles in =temp/<id>= below it, removed with the container, and the whole directory is removed by an =atexit()= handler (or =gsurf_runtime_dir_cleanup()=). Directories of dead processes are swept when a process creates its own; liveness is an =flock()= on the directory's =lock= file, so it works across PID namespaces.

The =gsurf= binary also calls =gsurf_runtime_dir_enter()=, which records the launch directory and =chdir()=s into the runtime directory, so a relative write by WebKit cannot reach the user's directory. *The library never changes an embedder's working directory*: a host such as cmacs keeps its own, and =gsurf_get_launch_dir()= then simply returns the current directory. A host that wants the same protection calls =gsurf_runtime_dir_enter()= itself before creating its first view. Relative paths from users or config files resolve with =gsurf_resolve_path()= (also used by =gsurf_expand_home()= and =gsurf_view_normalize_uri()=), which works either way.

* Control socket

The library never opens a control socket on its own. An embedder that wants =gsurfctl= (or any JSON-RPC client) to reach it starts one after activating its modules:

#+begin_src c
#include <gsurf/control/gsurf-control.h>   /* needs json-glib-1.0 */

g_autoptr(GError) error = NULL;
GsurfControlServer *control = gsurf_control_server_new(app);   /* or NULL: the module manager's */

gsurf_control_server_set_name(control, "cmacs");               /* optional: gsurfctl -i cmacs */
if (!gsurf_control_server_start(control, NULL, &error))         /* <runtime dir>/control.sock */
	g_warning("control socket: %s", error->message);
/* ... */
gsurf_control_server_stop(control);
g_object_unref(control);
#+end_src

The socket goes into the runtime directory (=gsurf_runtime_dir_get()=), so it disappears with it. =open= creates views as the gsurf binary does and relies on the host's =view-added= wiring; =action.run= performs the core actions only when the host registered an action executor (=gsurf_module_manager_set_action_executor()=). Extra methods come from =GsurfControlProvider= modules or =gsurf_control_server_add_method()=; =gsurf_control_server_dispatch()= runs a request in-process without a socket. =GsurfControlClient= and =gsurf_control_list_instances()= let a host talk to other gsurf instances. See [[file:control.org][control.org]].

* GObject Introspection

=make BUILD_GIR=1= produces =Gsurf-0.2.gir= / =Gsurf-0.2.typelib=, so gsurf can be
called from any introspected language. The abstract API exposes no GTK/WebKit
types, keeping the typelib backend-agnostic.

* cmacs (future)

cmacs currently drops the source view in its =create-view= handler and opens the popup URI itself. To give its buffers the same tree and container behaviour as standalone gsurf it should create the popup with =gsurf_view_new_full(source, NULL, uri, TRUE)= and record =gsurf_view_get_opener_id()= per buffer.

gsurf's clean GLib/GObject API and GTK-free abstract surface are designed so a
=GsurfView= widget can later be embedded as a buffer/overlay in the cmacs Emacs
fork via GObject Introspection. The library makes no GTK-main-loop assumption
(it uses the default GLib main context), which a host event loop can integrate.

* Ownership and view-removal contracts

Membership is unique by object identity: adding the same view to a window, or the same window to an application, more than once is a no-op. Duplicate additions do not take extra references, insert native widgets, connect extra close handlers, or emit addition signals. One removal or window close therefore removes that membership completely.

=gsurf_window_set_active_view()= only selects views already added to that window. Requests for foreign or previously removed views are ignored. The active pointer borrows the reference owned by the view list; it never retains an unowned view supplied by a caller.

String setters on boxed values, =GsurfSettings= and =GsurfDownload= duplicate their input before releasing the previous value. Borrowed getter results and substrings of those results can therefore be passed back into the corresponding setter. Existing NULL/default semantics are retained.

Removing an active view selects the view now at the removed index, or the previous final view when removing the last index. The backend receives the switch and =active-view-changed= is emitted after the public active-view pointer changes. Removing the final view emits the signal with NULL; signal consumers must handle an empty window.

A retained native WebKit widget or content manager must not deliver callbacks into a disposed =GsurfView=. GTK3 also disconnects the wrapper's shared-context callback. Likewise, a window retained by an embedder disconnects its application close handler when the application is disposed.

The opt-in GTK3 lifetime regression can run on the host's existing display without presenting a window:

#+begin_src sh
make test
GSURF_TEST_GUI=1 LD_LIBRARY_PATH=build/release ./build/release/test-backend-lifecycle
#+end_src

Ordinary =make test= skips this native test unless =GSURF_TEST_GUI= is set. The fake-backend window tests and string-ownership tests always run headlessly.
